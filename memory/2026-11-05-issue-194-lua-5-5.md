# Foundation の Lua を 5.5 へ更新 (#194)

- `tools/lua/build.py` は 5.5 だけを受け付ける（5.4 と併存させない）。検証は lua.org の `lua-5.5.1.tar.gz`、Newlib 4.4.0.20231231、Clang 20.1.8 + llvmlite 0.50。`lua.wax` は 2,386,096 byte（5.4.9 より約 84 KB 増）で、3 MiB staging に収まる。パッチなし、`-DLUA_USE_JUMPTABLE=0` も同じ。
- 5.5 の `lua.h` は版を数値マクロ（`LUA_VERSION_MAJOR_N 5`）で定義し、文字列マクロは `LUAI_TOSTR` 経由。`lua_version()` は両形式を読む。5.4 のソースを渡すと「not a Lua source tree」ではなく「Lua 5.5 only (got 5.4.9)」になる。
- 5.5 の float の文字列化は `%.15g`、往復しなければ `%.17g`（5.4 は `%.14g`）。`math.pi` は `3.1415926535897931`、`0.1 + 0.2` は `0.30000000000000004`。`test_lua.py` の期待値はこの変更に合わせた。実機の出力でなく Python で別に計算した値。
- `global` 宣言、`for` 変数の const 化、名前付き可変長引数（`...t`）、`table.create` はディスク起動で確認。`global a, b` の後は宣言していない名前（`table` など）がコンパイルエラーになる。スコープは `do ... end` で閉じる。
- `collectgarbage('generational')` が `generational` を返すのは正常（`lua.c` が起動時に世代別へ切り替える）。
- 16 MiB RAM の枯渇テスト（`string.rep` の連結を積む）は、保持量が 5.4.9 の約 5 MiB から約 3 MiB に減った。原因は未調査。`not enough memory` からの回復は同じ。
- 検証: `CLANG=... SRC32_LUA_WAX=... python -m unittest discover -s foundation/tests/lua -v` を `cached`、`FOUNDATION_TEST_CPU=pipeline`、`FND_MM=nommu` で実行。Git Bash で `MSYS_NO_PATHCONV=1` を export したまま `SRC32_LUA_WAX=$PWD/...` を渡すと `/c/...` が変換されず FileNotFoundError になるので、`pwd -W` を使う。
