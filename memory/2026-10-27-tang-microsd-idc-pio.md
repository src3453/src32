# Tang MicroSD dd0 / PIO IDC

- Tang RTL now exposes MicroSD at IDC slot 0 with standard offsets and byte DATA PIO. Hardware +0x3c bit0 advertises PIO; there is still no DMAC. The emulator remains the DMA reference and its SDK DMA helpers cannot be used on the Tang profile.
- `FND_PLATFORM_TANG` routes dd0 through PIO, a 512-byte kernel buffer and `mm_copy_*`. dd1 retains the separate SDRAM disk window. UART-loaded Tang boot explicitly selects boot drive 1, preserving the RAM-disk root while a valid FS2 card mounts at `/dd/0`.
- Rebuild old Tang kernels: an old kernel interprets dd0 as SDRAM. Other platform builds retain the existing DMA/IRQ backend.
- `foundation/tests/console/ramdisk_host.c` now checks both dd1 boundaries/access checks and dd0 identify, 2-sector PIO, virtual-user copies and error translation. Run `python -m unittest discover -s foundation/tests/console -p test_headless.py`.
- Build checked with `python foundation/boot/build.py target/foundation-microsd --platform tang-console -j 4`. On Windows sandboxed Clang needs workspace-local TEMP/TMP; native Icarus/Gowin may require normal host execution.
- See adjacent RTL repository `doc/microsd.md` for physical SD details, BIOS raw protocol, exact emulator comparison exclusions and physical test procedure. This change does not add SD auto-boot or alter the standard DMA-based stage1.
- On-board validation: the rebuilt image booted with dd1 as root; `test_foundation_board.py` passed uname/free (16384 KiB RAM), root FS2 write/read/copy and directory checks. On the 32001C retail carrier, the inserted 32 GB card still returns no CMD0 response (`0x000400ff`, RX=FF), even after a power cycle. Do not claim physical MicroSD I/O passed: no card sectors were written or formatted. The MCU/FPGA MUX selection is not yet measured/verified, and BL616's signed boot stage/custom firmware flash were left untouched.
- Final diagnostic FPGA: `../src32-sv/build/microsd-trace/prj/soc_top/impl/pnr/soc_top.fs`, Fmax 48.621 MHz against 48 MHz with 0.8 ns margin; SRAM programmed. RTL, live emulator comparison and Gowin SP2 post-synthesis card-model checks passed. All four USB DTR/RTS states still yielded CMD0 RX=FF and were restored to false/false. MCU help/uart_info and return via choose uart were used; no GPIO16 API was found. PC-connected bridge and standalone custom firmware are separate modes per the user's linked nand2mario article, so a custom-layer rewrite is not a verified solution and was not attempted.

- Follow-up: the user relaxed the SPI requirement. The FPGA default now uses the 486Tang-derived native four-bit SD engine (SDHC/SDXC, CSD v2); the old SPI backend is retained for comparison. The public IDC PIO/BIOS interfaces and Foundation dd0/dd1 mapping stay the same. Native CMD9 capacity/write protection, all-lane CRC16, a sector-buffer adapter, 400 kHz initialization/6 MHz data clock enables and bounded timeouts are added. Native RTL, real CPU/BIOS/UART tests and Gowin SP2 post-synthesis tests pass; the live emulator comparison matches both the 1024-byte read hash and all 4096 committed media bytes. Source provenance/license and supported cards are documented in adjacent RTL repository soc/native_sd/README.md and doc/microsd.md.

- Native physical qualification: after re-inserting the card while the native FPGA image was active, IDENTIFY reports 62,410,752 sectors (31,954,305,024 bytes), CSD 400e00325b590000ee137f800a40004d. BIOS raw tests passed address/inverse/zero/ones on LBA0..7, including immediate/later verification and restoring the 4 KiB backup. A 1 MiB FS2 test image was then written/verified; the rebuilt Foundation read its /dd/0/probe.txt, created/read /dd/0/fpga-sd.txt, copied it to /dd/0/testdir/copy.txt and to the dd1 RAM root, with all contents matching. Native bitstream: build/microsd-native-fixed2/prj/soc_top/impl/pnr/soc_top.fs, 48.010 MHz with 0.8 ns setup uncertainty, 38,685 LUT/ALU, 20,090 FF, 265 BSRAM, 20 DSP. Native post-synthesis regression also passed at physical INIT_DIV=60. Runtime data clock remains 6 MHz; an experimental 400 kHz data transfer returned error, and cold-start card-mode/ownership handoff is not qualified. No BL616 layer was flashed. Earlier no-response/different-CSD observations are superseded by the qualified inserted-card run, not a proven explanation of their cause.

- Persistence/cleanup: stopped guest execution by SRAM-reloading the qualified image, read all 2048 test-volume sectors back, ran the host full FS2 structural check with DIRTY allowed, verified both saved files contained microsd-kernel-write-ok, then cleared DIRTY in a host copy and passed the ordinary full check. Wrote only the verified clean superblock at LBA1 and read-back verified it. Card retains the 1 MiB FS2 test volume; board is at BIOS boot>. Snapshot artifacts in adjacent src32-sv/build: sd-fs2-after-kernel.img and sd-fs2-after-kernel-clean.img. BL616 flash remains unchanged. This does not qualify automatic power-on boot/card ownership; insert the card after loading the native SRAM image when switching configurations.
