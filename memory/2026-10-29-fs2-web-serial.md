# FS2 Web シリアル更新

- Tang BIOS の I/D/W を利用し、Foundation と同時アクセスしない。全イメージを既存 fs2.py で検査し、変更を準備してから DIRTY を書く。
- セクタごとに読み戻し、全変更完了後に DIRTY を解除する。既存 DIRTY は拒否し、失敗後の修復は行わない。
- 検証: `python -m unittest discover -s tools/fs2-web -p "test_*.py"` と `python -m unittest discover -s tools/fs2`。

- BIOSはリセット後1秒で自動起動するため、先にポートを開いて `?` を反復送信し、ユーザーにリセットしてもらう。SD IDENTIFYの失敗は最大約20秒かかる。
- 全セクタの読み取りは実機で約35秒/1024セクタ。大きいボリュームでは進捗を表示する。
- 一覧とダウンロードは必要なセクタをオンデマンドで読み、局所構造を検査する。媒体全体の整合性を保証しないため、更新時は全体検査を省かない。
- 復元はイメージ全体を事前検査し、媒体容量を確認してからsuperblockをDIRTYにし、残りを読み戻し付きで書く。元のDIRTYは保存し、cleanのイメージだけ最後にDIRTYを解除する。
- DIRTYレスキューは事前の元画像保存後、bitmap再構築と未到達inodeの解放だけを行い、共有ブロックや壊れたディレクトリ等は拒否する。完全検査に通るまでは媒体を変更せず、DIRTYは最後に解除する。
