# Rust ゲスト（ベアメタルと Foundation）を llvm-src32 で作る

- 経路: `tools/llvm-src32/cargo_src32.py` が `cargo rustc --crate-type staticlib --target tools/llvm-src32/rust/src32-none.json -Zbuild-std=core[,alloc] -Zjson-target-spec -- --emit=llvm-ir=PATH` を実行し、fat LTO 後の 1 モジュールを globaldce してから `driver.py` に渡す。ターゲット JSON は Clang の `mips-unknown-none` o32 と同じ data layout（driver はレイアウト文字列の完全一致を要求する）。`max-atomic-width: 0`（バックエンドは atomic を拒否するので、atomic 型自体を cfg で消す）。
- `--emit=llvm-ir` と fat LTO を組み合わせると、rustc が書く IR は **LTO 後**で、依存クレートと core を全部含む（`-C lto=fat` なしだとクレート単体の IR になり core が欠ける）。`compiler_builtins` は `#![no_builtins]` なので LTO に入らない。`memcpy` 等は driver の runtime、浮動小数点は SoftFloat が埋める。IR 段階では i64 除算などの libcall は出ない。
- **opt-level 0 の LTO は未使用の internal 関数を消さない**（約 3000 関数、`f16` を使う core の関数を含む）。バックエンドは定義された関数を全部コンパイルするので `half` で落ちる。`-C passes=globaldce` は効かなかった。llvmlite の新 PM（`create_pass_builder` に MIPS の target machine、`add_global_dead_code_eliminate_pass`）で消している。llvmlite 0.50 は MIPS ターゲットを含む。
- IR の出力先は target dir 内の固定パス。Cargo が fresh と判断すると rustc を呼ばず IR も書かないため、一時ディレクトリに出すと 2 回目以降に IR がない。固定パスなら前回の同一 IR が残る（消えていたら `cargo clean -p` して再ビルド）。
- rustc の LLVM メジャー版と llvmlite のメジャー版が違うとテキスト IR を読めない。Rust 1.96 stable = LLVM 22.1、llvmlite 0.50 = LLVM 22.1 で一致。stable では `RUSTC_BOOTSTRAP=1` を付ける（`-Zbuild-std`、JSON ターゲットは nightly 機能）。`cargo_src32.toolchain_problem()` が理由を返し、テストはそれで skip する。
- rustc の IR が要求してバックエンドに足したもの（`test_toolchain.py::test_rustc_intrinsics_and_constants` が Rust なしで確認）: `llvm.experimental.noalias.scope.decl`（無視）、`llvm.trap`（HALT して自己ループ。U モードでは HALT が例外になる）、`llvm.fpto{s,u}i.sat`（Rust の `as` は飽和。SoftFloat の `f64_to_i32_r_minMag` は範囲外で 0x80000000 を返すので使えず、`rt.c` に `__src32_fix*_sat` を追加、32 bit 未満の結果はバックエンドで再クランプ）、`llvm.[su]cmp.i8.iN`（`Ord::cmp`、i64 は上位語が等しいとき下位語を符号なしで比較）、`llvm.is.constant`（常に偽）、`llvm.{s,u}{add,sub,mul}.with.overflow.iN`（debug ビルドのオーバーフロー検査と `checked_*`）、空テンプレート・出力なしのインライン asm（`core::hint::black_box`）、定数中の `undef` 配列／構造体（パディング。0 で埋める）。
- `{ iN, i1 }` を狭い N でスロットに書くときは big-endian なので `ST` ではなく `STB`/`STH` で offset 0 に書く（`ST` だと値が offset 3 に入る）。i1 の位置は `layout.offset(type, 1)`。
- `cpt32` の関数を何も使わないクレートは依存がリンクされず `#[panic_handler]` が見つからない。`use cpt32 as _;` が必要。`fnd::main!` は `$crate` を参照するので fnd では起きない。
- Foundation のコマンドは `--foundation-wal OUT/root/lib/fnd.1.wal`（= `--wax3 --page-align --pie --import-wal`）。import の signature 検査があるので `sys.rs` の extern は u32/i32/ポインタだけ。`fnd_exit` は `-> !` で宣言してよい（IR は `void` + noreturn）。
- Git Bash の heredoc（`<<'EOF'`）経由で Python スクリプトやファイルを書くと `\\` が `\` に潰れることがあった（正規表現 `[\\/]`、f-string の `\\n`）。バックスラッシュを含む内容は Write/Edit ツールで書く。
- 検証: `python -m unittest discover -s tools/llvm-src32 -p test_rust.py`（conformance を opt-level 0/2 × pipeline/cached、panic の UART 出力、ベアメタル例の PCG）、`python -m unittest discover -s foundation/tests/rust`（`rsdemo` をシェルで実行、`FND_MM=nommu` でも通過）、`python -m unittest test_toolchain.ToolchainTests.test_rustc_intrinsics_and_constants`（tools/llvm-src32 で）。
