# 34SI22 録音・再生インターフェース（SGU v3）

- 34SI22 は MSM6258 と同じ考え方の、ADC／DAC とメモリのあいだで標本を流すだけのチップ（`doc/spec_34SI22.md`）。将来単体で使う前提なので、コア（`src/devices/sgu/si22.rs`、FPGA は src32-sv `soc/si22.sv`）はホストに依存しない。メモリは `Si22Memory`（24 ビットのバイトアドレス）、ADC は `tick` の引数。CPT32 固有の部分（PCM RAM の 1 MiB 折り返し、MMIO `0x80022000`、SGU ミキサーへの加算、OS の録音デバイス）は `sgu.rs` の `Si22Unit` に分けてある。コアに CPT32 の事情を持ち込まない。
- `si22.rs` は src32-sv の `sim/sgu_golden/sgu_golden.rs` から `#[path]` で**無改変のまま**取り込まれる。`super::sqv4` 以外（crate 内の他モジュール、外部 crate）に依存させるとゴールデン比較がビルドできなくなる。
- 元の仕様案から補った契約: 形式レジスタ `0x21`／`0x22`、VOX の `0x23`／`0x24`、L/R は ENABLE ではなく **DISABLE**（リセット 0 で両側に出る）、W 属性のレジスタも読み戻せる、CTRL=1／2 は動作中なら無視し 3 は「変更しない」（読んだ値を書き戻しても再始動しない）、SQV4 はヘッダ付きで録音終了時にヘッダを書く（SGU の WAVEFORM 4 でそのまま再生できる）。
- （SQV4 版 2 当時）SQV4 録音は**バイトがそろうたびに書く**（音量バイト 255 はフレームの最初の標本のとき）にしていた。RTL は書き込みバッファで逐次書くため、録音途中の PCM RAM までそろえるためだった。SQV4 版 3（`2026-10-30-sqv4-v3-normalized-fragments.md`）では音量がフラグメント 23 標本のピークで決まるので、フラグメント完成時にまとめて書く方式に変わった。RTL は版 2 のままで、ゴールデン比較は RTL 更新まで一致しない。
- `0x1C` に 0 を書くと SQV4 録音はヘッダとパディングを書く（待機中の停止でも標本数 0 のヘッダを書く）。RTL ではこの処理をレジスタ操作の中でエンジンが行うので、そのレジスタ書き込みの ACK は最大 150 クロック程度遅れる（標本周期の処理中に来たレジスタ操作も、処理が終わるまで待つ）。
- エミュレータでは録音デバイスを、ゲストが最初に録音を始めた（状態 1／2）か REC_x_ADC（`0x25`～`0x28`）を読んだときに開く（`Si22Unit::wants_adc`、`GuiApp::audio_input_tried`）。起動しただけでマイクを使用中にしないため。デバッガの読み出し（`debug_read`）は数えない。デバイスがなければ無音を録音する。testbench には録音デバイスがなく、ADC は常に無音。
- REC_x_ADC は「最後に処理した tick の生の ADC 値」。RTL では取り込みレジスタ（`adc_q*`、`fs_tick` で更新）とは別に、標本周期の処理を始めるときに `adc_r*` へ写して公開する。`fs_tick` と同じクロックではレジスタ操作を始めない。こうしないと、処理前の tick の値が見えてエミュレータと 1 標本ずれる。
- 34SI22 の PCM RAM への書き込みで、エミュレータの SGU の SQV4 復号キャッシュは無効化されない（仕様 §10 に記載）。
- 検証: `cargo test --lib sgu`。RTL 比較は src32-sv で `python scripts/si22_gen_scripts.py` → `python scripts/sgu_cmp.py`（`--pcmlat 20`、`--x2` も）。比較スクリプトでは chip 2 が 34SI22、`I l r` が ADC 入力、`D addr len` が PCM RAM のダンプ（RTL は書き込みバッファが空になるのを待ってから読む）。
- 未確認: Gowin での合成・タイミング、実機での動作。
