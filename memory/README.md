# memory/ — 作業で得た知識・注意点

将来の開発者が同じ間違いをしないための記録です。過去の記録は `MEMORY.md`（アーカイブ）にあり、新しい記録はここに置きます。

## なぜ 1 作業 1 ファイルか

以前は全員が `MEMORY.md` の末尾付近へ追記していたため、並行する PR が同じ位置を編集してコンフリクトしました（#145、#155）。作業ごとに**新規ファイルを作る**と、他の PR と同じ行を編集しないので衝突しません。

## 書き方

- ファイル名は `memory/YYYY-MM-DD-issue-NNN-短い英語スラグ.md`（例: `2026-10-24-issue-154-sgu-v21.md`）。日付は作業日、`NNN` は Issue 番号です。Issue がない作業は `issue-NNN` を省きます。
- 先頭に `# タイトル` を 1 つ。続けて、契約・テストの意図・落とし穴を箇条書きで書きます。何を実行すれば検証できるか（focused なコマンド）も添えます。
- 1 ファイルは 1 つの作業の話題に絞ります。既存ファイルと同じ名前を作らないでください。
- **索引ファイルは作りません。** 索引も共有ファイルなので衝突します。探すときは `ls memory/`、`grep -ril <語> memory/ MEMORY.md` を使います。

## 既存の記録を直すとき

- 自分の作業の記録は、その PR の中で自分のファイルを直します。
- 他の作業の記録が古くなったときは、そのファイルの該当箇所だけを編集します（末尾追記ではなく局所編集）。`MEMORY.md` の節を直すときも同様です。
- `MEMORY.md` へは新規追記しません。
