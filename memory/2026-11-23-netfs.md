# netfs と /net（CFP の Foundation クライアント）

- 日付: 2026-11-23
- Issue: なし（ユーザー指示で作成せず）
- 仕様: `doc/spec_NET_FP.md` §11、`doc/spec_Foundation_API.md` §9.7（操作 `0x0500` NET_SET、`0x0510`+n NET_FS、`0x0580–0x0582`）、`doc/spec_FS2.md` §11.1（予約名 `net`）、`doc/spec_Foundation_shell.md`（`netfs`）。
- 実装: `foundation/services/netfs/main.c`（同梱モジュール）、`foundation/bin/netfs.c`（コマンド）、`foundation/fs/server.c`（/net の経路）、`foundation/fs/main.c`（ワーカー）。

## 決めたこと・落とし穴

- **サービスの登録には `FND_CAP_SVC` が要り、子の caps は親の部分集合**（`kernel/proc.c`）。シェル（init の caps は 0）から起動したプログラムは `svc_register` できない。最初は `netfs --service` をコマンドから起動する設計にして、登録できずに TIMEOUT になった。netfs は fs・pipe と同じく FNDBOOT の同梱モジュールにした（`boot/build.py` の specs、init より前）。モジュールの一覧と pid を固定しているテスト（`tests/disk/test_disk_boot.py` の modules、`tests/shell` の ps・top）も直した。新しい同梱サービスを足すときは同じ箇所を直す。
- 同梱モジュールは静的 WAX で WAL を import しないので、netfs は `lib/l3p/l3p.c` と `lib/cnet/cnet.c` をソースでリンクする。L3P の状態（約 9 KiB）は mount している間だけ `fnd_mem_alloc` する。何も mount していなければ `ipc_recv` は FOREVER、mount があれば 10 tick ごとに起きて `l3p_poll`（再送とキープアライブ。L3P の無通信タイムアウトは 120 秒）。
- fs の単一スレッドを止めないため、`/net/<名前>` の下の要求は `fs_rep.net` で main.c に返し、main.c が非公開の PORT 経由でワーカー（2 本）に渡す。ワーカーは受け取ったらすぐ main に ack し、netfs を呼んでクライアントのトークンに `ipc_reply` する（トークンはプロセス内のどのスレッドからでも応答できる。`kernel/ipc.c` の `token_caller` は `wait_proc` だけを見る）。cwd の設定はセッションを持つ main にしか触らせず、ワーカーは内部オブジェクト（`OBJ_INTERNAL`）の CHANNEL で `FS_NET_CWD` を送る。
- **thread_create の引数レジスタは使わない**（ツールチェーンの C ABI として文書化されていない）。ワーカーごとに入口関数を分けた。
- /net を通るパスは fs が文字列の上で `.`／`..` を処理する（`net_canon`）。結果が `/net/<名前>` の下なら転送、外なら正規化したパスでローカル探索。`np->buf` は `net_path` の**最後**のメンバーにすること（`memset(np, 0, sizeof *np - sizeof np->buf)` で先頭を消すため。最初に先頭に置いて全テストが NAME_TOO_LONG になった）。末尾の `.`／`..` はディレクトリを指すので、転送するパスに末尾の `/` を付ける。
- **libl3p の NONCE が再起動で繰り返していた**。tick・アドレス・ソケット・カウンタだけから作っていたので、決定的なエミュレータで同じ tick に mount すると同じ NONCE になり、サーバー（`tools/l3p`）は既知の（ノード、ソケット、NONCE）に古い結合の ACCEPT を黙って返す。その結合の XID は使用済みなので要求が通らず TIMEOUT。エミュレータの RTC は既定で 0 から数える（REALTIME でない）ので RTC だけでは足りない。プロセスごとに一度 `/dev/trng`（ホストの乱数）から種を取って混ぜた（spec_NET_L3P §4.1 に追記）。同じサーバーに 2 回起動して確かめるテストが `test_mount_again_after_a_reboot`。
- `foundation/tests/fs` の `/dev` の一覧の期待値に `cnet` がなく、この作業の前から失敗していた（cnet ノードを足したときの直し忘れ）。直した。

## テスト（2026-11-23、Windows、clang 20）

- `CC=clang python -m unittest discover -s foundation/tests/fs`（34 件。NetTests が転送するパス、fs が自分で答えるエラー、/net を通ってローカルに戻るパス、/net の下の cwd）。この環境では `cc` がないので `CC` に LLVM の clang を指定する。
- `CLANG=... python -m unittest discover -s foundation/tests/cfp -v`（5 件、約 90 秒）と `FND_MM=nommu` の同じテスト。testbench の Foundation と同じプロセスの `cfp_server.py`（ノード FF02、ホストの一時ディレクトリ）。exports のブロードキャスト、mount・一覧・ls・cat、書き込み・追記・mkdir・cp（10 KiB）・mv・rm・rmdir（NOT_EMPTY）・/tmp への mv（CROSS_DEVICE）、cd と相対パス、読み取り専用 mount、エラー表示、再起動後の再 mount。kernel の停止 tick を 3000 にした専用イメージを setUpClass で作る。
- 未確認: セッション喪失時の STALE と再接続（シェルからは時刻を合わせにくい）、ネットワーク待ち中にローカル操作が進むこと（同時に 2 つのプロセスが要る）、`-e`（libl3p が暗号化未対応）、FS2 イメージの輸出への mount。
