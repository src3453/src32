# SGUB v4（34SI22、タイマ周期、カード要件表）と 3HS816 カード

契約は `doc/spec_SGUB_v4.md`。3HS816 カードは `doc/spec_3HS816.md` の「CPT32 拡張カード」節。Furnace 側の記録は Furnace の `MEMORY.md`「SGUB v4」節。

- **v4 は v3 と同じ 7/11/16 byte の操作で、ヘッダーが 48 byte**（`header size` = 48、`0x26` にカード要件数、`0x28` に `frame_period`）。pool directory は `48 + 32 × カード数` から。v2/v3 の reader の経路は変えていない。v1〜v3 のファイルはバイト単位でそのまま読める。
- **target 11 = 34SI22 レジスタ（WRITE のみ、`0x00..0x3F`）**。標本は target 2 の共有 PCM RAM。終端の停止処理は「stream が target 11 を使ったときだけ」PLAY_CTRL に 0 を書く。SGU v2 の構成では `0x80022000` が未マップなので、使っていない stream で書くと bus error になる。
- **カードは種類を推測しない**。カード要件表の ID bytes を MMIO で読んで照合し（`sgub_init` が初期化の前に行い、不一致は `SGUB_STATUS_ERROR_DEVICE` = -8）、FILL/COPY_POOL は表の bulk window の内側だけ許す。3HS816 は window なし（WRITE のみ）、3WS88PWN4 は `0..0x400000`。カードへの bulk は 32-bit でまとめず byte 単位（`target < 3` だけ 32-bit）。
- **タイマ駆動は guest driver の仕事**。`sgub.c` は 1 フレーム進めるだけで、`sgub_state()->frame_period` を見て driver が PeC timer 0 を periodic（RESET → PRESCALER 0 → COMPARE = RELOAD = period → TIMER_ENABLE → CTRL 0x0D）にして IRQ4 で `sgub_step` を呼ぶ。handler は先に `TIMER_ACK` を書く（IRQC の pending は dispatcher が ACK）。Foundation の `sgubplay` は OS tick の累積で周期を作る（64-bit で `elapsed × 48e6` と `hz × period` を比べる）。
- `StreamPlayer::take_card_writes()` は `(target, address, value)` を返すようになった（target 3..10 が slot、11 が 34SI22）。`advance_vsync` は「1 フレーム」の意味で、v4 のタイマ周期の stream ではホストが `frame_period()` ごとに呼ぶ。GUI の SGUB Player（`music::monitor`）は 800 sample ごとに呼んだままで、v4 の周期とカード・34SI22 の音は未対応（#203 側の作業）。
- **testbench の `--expect-mem-u8` は毎フレーム検査する**。最初のフレームの前に 50M サイクルの起動予算があり、その間にタイマ IRQ は何十回も来るが VSync は来ない。タイマとVSyncを区別するテストは `--expect-final-mem-u8` で最終状態だけを見る（VSync にすると 8 で止まり、タイマだと 10 まで進むことを確認済み）。
- 3HS816 カード（`examples/wasm-3hs816`）は C++ モデルの逐語移植。`tests/script.txt` を両方で再生し、C++ の出力 `tests/reference.pcm` と全サンプル一致を確かめる。表は `chips/3hs816/src/generated_tables.hpp` から `tools/gen_tables.py` で生成し、テストがヘッダーとの一致を検査する。C++ を直したら Rust も同じ変更をして fixture を作り直す。
- Furnace の 3HS816 は reset でフィードバックに 128 を書くが、チップのリセット値は 0（−1 倍）。register dump は `playSub()` の後に始まるので reset の書き込みは記録されない。exporter は frame 0 に `getRegisterPool()` のスナップショットを書く（これがないとカードの音色が変わる）。
- Furnace の実出力 `tests/fixtures/furnace_v4_mix.sgub`（S3W2 PCM + 34SI22 + 3HS816）は frame 6 から発音する（frame 0..5 は無音の tick）。34SI22 の bank は S3W2 PCM の後ろの `0x1010` に置かれ、START/STOP が移動済み。
- ヒアドキュメント（Git Bash）で Python を書くと `\\n`・`\0` が化ける（NUL やただの改行になる）。パッチ用スクリプトは Write で作ったファイルから実行する。
- Windows の ROCm clang は `-fPIC` を拒否し、DLL は何も export しない。`foundation/tests/sgub` のホストテストは Windows では `-Wl,/EXPORT:` を付ける。

検証:

```sh
cargo test --lib music::stream
cargo test --test furnace_sgub
cargo test --manifest-path examples/wasm-3hs816/Cargo.toml
python -m unittest discover -s tools/llvm-src32 -p test_toolchain.py -k sgub   # SRC32_TESTBENCH、wasm32 target が必要
python -m unittest discover -s foundation/tests/sgub                         # HOST_CC、testbench、Clang
```

Furnace 側: `test/sgub` の CTest（`writer.cpp`）と `python test/sgub/v4_check.py build/Release/furnace.exe`。
