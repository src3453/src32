# WASMネットワークカードと権限モデルの検討

- ユーザーの要件は、WASMカードのバックエンドに権限システムを設け、リスクの高い外部アクセスはユーザーが明示的に許可した場合のみ行うこと。以下は設計案であり、実装済み契約や採用決定ではない。
- 現行ABI v1はWASIを提供せず、`src/devices/expansion.rs` のimport検査で6種類の `cpt32_host` 関数に限定する。権限付きネットワークにはホスト、ABI仕様、SDK、package builder、設定、UI、テストの拡張が必要。
- `src/devices/expansion/package.rs` のmanifestは `deny_unknown_fields` を指定するため、現状のpackageへpermissionsフィールドを足すだけではロードできない。旧ホストとの互換性・形式バージョンの扱いを明示する必要がある。
- 検討案はMMIOのTCP/UDPオフロード型カードと、ホスト側の権限検査付き非同期ネットワークサービス。Ethernet型はゲストTCP/IPスタックを必要とし、bridge/raw権限と接続先制限の組み合わせも別途設計する。
- manifestの要求は許可ではない。ホスト側でユーザー承認を保持し、対象・操作・宛先を絞る。DNSも外部アクセスとして許可前に実行しない。解決した接続先IPを検査し、検査したIPに接続して再解決によるすり抜けを防ぐ。
- 権限取消・reset・faultでは接続と保留要求を破棄し、世代番号で古い完了通知を排除する案。デバッガ読み出し・音声呼び出し・初期化から外部アクセスが起きないようホスト側で呼出し種別を検査する。
- 実装時は拒否時にDNS/通信が発生しないこと、loopback/LAN/IPv6等の宛先制限、権限取消、カード間handle分離、キュー上限、旧カード互換性を検証する。今回はソースと仕様の読解のみで、動作テストは実行していない。
