# WASM カードの GUI パネル（`gui` capability）と CNET カードのパネル

- 契約は `doc/spec_WASM_expansion_card.md` §3.4。manifest の `capabilities: [gui]` で、カードは `cpt32_ui` export と `ui_*` import（text / text_colored / separator / same_line / button / checkbox / input_int / input_text）を使える。宣言のないカードが `ui_*` を import すると起動エラー、宣言したのに `cpt32_ui` か `memory` の export がなければ起動エラー。SDK の `export_card!` はすべてのカードで `cpt32_ui` を export するので（`cpt32_net_rx` と同じ）、ホストは宣言のあるカードにしか呼ばない。
- **immediate mode で 1 フレーム遅れ**。カードは `cpt32_ui` の中で widget を上から記述し、ホスト（`src/devices/expansion/ui.rs` の `UiHost`）が `ExpansionUiItem` の列として記録する。GUI の操作は widget ID ごとの `ExpansionUiEvent` として積まれ、**次の** `cpt32_ui` で同じ ID の import の戻り値になる。イベントはその呼び出しの終わりに捨てる（対応する widget がなくても）。カード reset でも捨てる。ImGui の `Ui` を wasmtime の import に渡さない設計なので、ヘッドレスで `Bus::expansion_card_ui(slot)` / `expansion_card_ui_event` を呼んでテストできる。
- `cpt32_ui` は普通の guest 呼び出し（fuel 上限・fault は同じ、`ExpansionCallKind::Ui` で計測）。カードの状態変更や `irq_set`／`net_send` を呼んでよいので、`Bus::expansion_card_ui` は呼び出し後に `refresh_device_irqs` する。`ui_*` を `cpt32_ui` の外で呼ぶと trap。testbench／monitor は呼ばないので、ゲストの動作をパネルに依存させない。
- ABI 違反（trap）: 文字列 256 byte 超、1 回 512 widget 超、入力 widget の ID 重複、checkbox の値が 0/1 以外、input_int の min > max、input_text の len > cap > 256。不正 UTF-8 は置換文字で表示（trap しない）。`run_ui` の fault 理由は `{error:#}` で host のメッセージまで残す。MMIO などの既存 export の fault 理由は `{error}` のままで、host のメッセージが出ない（テストはそれを前提に書いた）。
- input_text は Enter で確定したときだけ buffer を書き換えて長さを返す（それ以外は -1）。GUI 側は毎フレーム card の値から `String` を作り直すが、編集中は ImGui が自分の buffer を使うので打鍵は消えない。実機の GUI でこの挙動はまだ見ていない。
- GUI（`src/main.rs`）: Overview 表の `gui` カードの行に 2 つ目のボタン「Panel」、Expansion Cards メニューに「Slot N panel」。パネルが開いている間だけ GUI フレームごとに 1 回 `cpt32_ui` を呼ぶ。faulted カードは呼ばず、fault 理由を出す。
- CNET カード（`examples/wasm-cnet`）は manifest が `[network, gui]` になった。パッケージを手で作っている所（`tests/cnet.rs` の `write_package`、`examples/cnet-chat/run_demo.py`、`foundation/tests/cnet/test_cnet.py`、README の `package.py` 例）もそろえた。`[network]` のままだと `ui_*` import で起動エラーになる。
- CNET パネルのカウンタは `send_link`／`receive_all` で数えるリンクフレーム単位で、probe や IN_USE も含む（テストで probe 4 個 = 48 byte が入るのを確認してからリセットしている）。速度は `current_cycles` の仮想時間 0.5 秒以上の区間で計算。Simulated TX loss はデータグラムのフレームだけを捨て（アドレス取得を壊さないため）、カード reset をまたいで保持する。Re-acquire はソケットを閉じずに probe をやり直す。
- 検証（2026-11-23）: `cargo build --manifest-path examples/wasm-cnet/Cargo.toml --release --target wasm32-unknown-unknown` → `cargo test --test wasm_ui --test cnet`、回帰に `--test wasm_expansion --test wasm_psg --test cpt32pkg_runtime --test sgub_monitor --test spin_fast_forward --test timing_insensitive_mmio --test cpu_relaxed`、`cargo test --lib expansion`、`python -m unittest discover -s sdk/wasm-expansion-card -p 'test_*.py'`、`python -m unittest discover -s foundation/tests/cnet`。GUI は `cargo build --release --bin cpt32` が通ることだけ確認し、画面では見ていない。
