# pkcl（POSIX Kernel Compatibility Layer）M0

- 設計は `doc/spec_pkcl.md`、実装は `foundation/lib/pkcl` と `foundation/include/pkcl`、テストは `foundation/tests/pkcl`。fdio 相当の「コンパイル時に静的リンクする POSIX→libfnd 変換層」。サービスやカーネル ABI は変えない。
- BusyBox は GPL-2.0 なのでリポジトリに入れない（owner 指示）。外部ソースを指定してビルドする方式（Newlib と同じ）。パッチも同梱しない。
- 1 記述子 = 1 CHANNEL。読み書き位置はサービスが持つので `dup` は位置を共有する。fd 2 は役割がないと STDOUT と同じハンドルなので、`pkcl_init` が `handle_dup` で別ハンドルにする（片方の close でもう片方が壊れるため）。
- FS2 の mode は owner/other の 6 bit（POSIX の 0755 をそのまま保存できない）。変換は `pkcl_mode_to_fnd`／`pkcl_mode_from_fnd`。group は捨て、stat では other の複製。
- 定数は Newlib の値（ENAMETOOLONG=91、ENOSYS=88、O_CREAT=0x200 …）。libc を Newlib にしたとき食い違わないため。
- `off_t` は 32 bit。2 GiB 以上は `EOVERFLOW`。`fnd_seek` は libfnd にまだないので `lseek` は `ST_SEEK` を `fnd_call` で直接送る（i64 は hi, lo の順で a1, a2）。
- fork/vfork は作らない（ENOSYS）。BusyBox は NOMMU＋NOFORK で `posix_spawn` に寄せる。ギャップ（pid、環境、pipe、inode、utime、setjmp）は spec §7 と Issue #166〜#171。
- テスト環境: Clang と llvmlite の LLVM を揃える（`pip install "llvmlite==0.46.*"` と `clang-20`、`CLANG=/usr/bin/clang-20`）。揃っていないと `ptr type is only supported in -opaque-pointers mode`。`libasound2-dev libudev-dev` で testbench をビルド（`apt-get update` が先に必要だった）。
- 検証: `CLANG=/usr/bin/clang-20 SRC32_TESTBENCH=target/release/src32_testbench python3 -m unittest discover -s foundation/tests/pkcl -v`（約 35 秒）。
