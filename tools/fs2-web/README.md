# FS2 Web シリアル更新

Tang Console の BIOS モニターから dd0 の FS2 ファイルを追加・上書きします。Python と pyserial が必要です。

```
python -m pip install pyserial
python tools/fs2-web/server.py
```

表示された `http://127.0.0.1:8765/` を開き、COM ポート、ボーレート、FS2 の絶対パス、ファイルを選択またはドロップしてアップロードします。ダウンロードはFS2パスを入力して準備ボタンを押し、生成されたリンクをクリックするか、対応ブラウザーではリンクをドラッグします。転送ボタンを押してから60秒以内にボードをリセットしてください。ツールが `?` を送信してBIOSモニターに入ります。待機中の `?` は稼働中のFoundationにも入力されます。別のシリアル端末は閉じてから更新します。BIOS は `I`、`D`、`W` コマンドに対応したものが必要です。親ディレクトリは事前に作成してください。対象は dd0、FS2 容量は最大 64 MiB です。全セクタをシリアルで読み込むため時間がかかります。

FS2 全体を検査し、メモリ上で更新・再検査した後、DIRTY を先に書き、変更セクタを各々読み戻してから DIRTY を最後に解除します。途中で失敗した媒体は DIRTY のままになる可能性があります。自動修復は行いません。バックアップからの復元またはオフライン検査が必要です。Foundation 稼働中には操作しないでください。既に DIRTY の媒体は拒否します。電源断やSDカードの書き込み保証により復旧できない場合があるため、重要な媒体は先にバックアップしてください。

「一覧を読み込む」で必要なsuperblock、inode、ディレクトリのセクタだけを読み取り、ディレクトリをたどれます。読み取った構造は検査しますが、媒体全体の整合性は検査しません。ファイルを選ぶと転送先のパスが入力されます。一覧は読み込んだ時点のスナップショットで、更新後は再読み込みしてください。各ディレクトリを開く際に必要なセクタを読み取ります。

「イメージをバックアップ」でFS2ボリューム全体を読み取り、`fs2-backup.bin` として保存できます。DIRTYの媒体もバックアップできますが、修復やDIRTY解除はしません。各操作には進捗バーが表示されます。

ダウンロードも対象ファイルの参照に必要なセクタのみを読み、たどった構造を検査します。全体検査はアップロード時に行います。

「イメージを復元」でバックアップ `.bin` を選択し、復元ボタンを押します。SDのLBA 0からイメージ長の範囲を上書きするため、それまでのデータは失われます。事前に復元元を完全検査し、SD容量を確認します。復元先のsuperblockへDIRTYを立てた後、残る全セクタを書いて個別に読み戻し、最後に元のsuperblockを書きます。復元元がDIRTYの場合はDIRTYのまま復元し、修復や解除はしません。途中で失敗した場合は電源を切らず、エラーを確認してバックアップから再度復元してください。superblockの書き込みそのものが中断された場合などは、DIRTYが正常に残る保証はありません。

「DIRTYなFS2をレスキュー」は、DIRTY媒体の全イメージを `target/fs2-web-rescue/` に自動保存してから、ビットマップを再構築し、参照されないinodeとそのブロックを解放します。未到達ファイルは失われます。確認ダイアログで同意が必要です。共有・循環・範囲外ブロック、重複名、複数親、壊れたエントリ等の判断が曖昧な破損は修復せず、エラーと保存先を表示します。完全検査に通った場合のみDIRTYを最後に解除します。修復済みでもファイルの内容が完全である保証はありません。書き込み途中の障害では媒体が不完全な可能性があるので、保存された元イメージを保持してください。

アップロード先にはファイル名を含む絶対パス（例: `/hello.txt`）を指定します。ファイルを選択またはドロップしたとき、パスが空またはディレクトリで終わる場合はファイル名を自動補完します。

画面の左側でボード接続を設定し、ファイル一覧からフォルダーを開いたりファイルをダウンロードできます。バックアップ・復元・レスキューは「ディスクの管理」を開いて操作します。
