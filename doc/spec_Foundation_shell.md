# Foundation シェル仕様 v1

Revision 0.1、2026-10-22。Status: **ドラフト（主要な設計判断は確定、一部実装）**。fs、`proc_spawn`、console サービスがなくても動く部分を [`foundation/shell`](../foundation/README.md#シェル) に実装しています（実装済みの範囲と暫定の扱いは README）。 本書は Foundation OS の標準シェル `/bin/shell.wax` の起動、構文、展開、コマンドの解決と実行、リダイレクト、組み込みコマンド、スクリプト、対話入力を定めます。カーネル ABI は [spec_Foundation.md](spec_Foundation.md)、ファイルシステムと VFS は [spec_FS2.md](spec_FS2.md)、背景は [実装案 §7](foundation_os_plan.md) を参照してください。本書と実装案が異なる場合は本書が優先します。

「〜しなければならない (MUST)」「〜してはならない (MUST NOT)」「〜してよい (MAY)」は規範的な要求を表します。

## 1. 範囲と位置づけ

| 項目 | 値 |
|---|---|
| 実行形式 | `/bin/shell.wax`。PROTECTED WAX（v2、または v3 の `os_id = foundation`） |
| スロット | 4（`0x00600000–0x007FFFFF`、[Foundation §5.2](spec_Foundation.md)） |
| 優先度 | 2 APP。ケーパビリティは持たない（`caps = 0`） |
| 実装言語 | C11（freestanding）。ファイル、コンソール、プロセスの操作は libfnd を通す |
| 文字コード | UTF-8。メッセージは ASCII の英語 |
| 版 | シェル 1.0。起動時と `uname` が表示する |

本書が定めないもの：

- ファイル、ディレクトリ、コンソールの IPC プロトコルと libfnd の関数は [API 仕様](spec_Foundation_API.md) で定めます。シェルがその仕様に要求する機能は §12 にまとめます。
- サービスの起動とシェルの再起動の方針は init の仕様で定めます。

設計方針は次のとおりです。

- 組み込みコマンドの名前は UNIX に合わせます（`ls`、`cat`、`cp`、`pwd` など）。ただしコマンド名は大文字小文字を区別しません（`LS` も `ls` と同じ）。
- パスも UNIX 風です。区切りは `/`、オプションは `-x` です。
- 構文は小さく保ちます。v1 にない構文の記号（§3.3 の予約記号）はエラーにし、後の版で意味を与えられるようにします。

## 2. 起動と終了

### 2.1 呼び出し形式

```text
shell                       対話モード
shell -c <line>             <line> を 1 行として実行して終了する
shell <script> [args...]    スクリプト（§8）を実行して終了する
```

- 対話モードかどうかは引数だけで決まります。STDIN の種類は判定に使いません。
- `-c` とスクリプトの両方は指定できません。不明なオプションは使い方を STDERR に出して `FND_E_BAD_ARG` で終了します。
- 対話モードでは、起動時に OS とシェルの版を表示します（§10 の `uname` と同じ 2 行）。続けて `/etc/profile.fsh` が存在すればスクリプトとして実行します（§8）。存在しなければ何もしません。その中のエラーは表示しますが、対話モードには入ります。

### 2.2 起動ブロック

シェルは [Foundation §9.3](spec_Foundation.md) の起動ブロックから次を読みます。

| 項目 | 扱い |
|---|---|
| argv | §2.1 の引数 |
| cwd | 初期カレントディレクトリ。`fnd_cwd_set` で設定する。失敗した場合は `/` にしてエラーを表示する |
| `STDIN`、`STDOUT` | 必須。ない場合は `FND_E_BAD_HANDLE` で終了する |
| `STDERR` | ない場合は `STDOUT` を使う |
| `FS` | ない場合は libfnd の既定（`svc_lookup("fs")`）に任せる |
| `CONSOLE` | 対話モードで必須（行編集と Ctrl+C の検出に使う、§9）。ない場合は `FND_E_BAD_HANDLE` で終了する |

### 2.3 終了

シェルの終了コードは次のとおりです。

- `exit [code]` を実行した場合は、その値です（省略時は `$?`）。
- `-c` とスクリプトの実行では、最後に実行したコマンドの `$?` です。
- 対話モードで STDIN が終わった場合（`FND_E_PEER_GONE` など）は、`$?` です。

シェルは同時に 1 つしか動かせません（スロット 4 は 1 つしかない）。シェルの中から `shell` を外部コマンドとして実行すると `FND_E_ADDRESS_CONFLICT` になります。スクリプトは同じシェルの中で実行するため、この制約を受けません（§8）。

## 3. 字句

### 3.1 行

- 1 行は改行（LF。直前の CR は捨てる）までで、最大 1023 bytes です。超えた行は実行せず、`FND_E_LIMIT` にします。
- NUL を含む行と、不正な UTF-8 を含む行は実行せず、`FND_E_BAD_ARG` にします。

### 3.2 語と引用

語は空白（SP と TAB）で区切ります。次の記法で、空白や記号を語の一部にできます。

| 記法 | 意味 |
|---|---|
| `'...'` | 中身をそのまま使う。変数展開もワイルドカードも行わない。`'` 自身は含められない |
| `"..."` | 変数展開だけを行う。中で特別な意味を持つのは `$`、`\"`、`\\`、`\$` だけ |
| `\c` | 引用の外で、次の 1 文字を記号ではなく文字として扱う。行末の `\` はエラー（行の継続はない） |

- 引用は語の途中から始めて、引用していない文字と連結できます（例：`a"b c"d` は 1 語 `ab cd`）。
- `""` と `''` は空の語になります。
- 閉じていない引用はエラー（`FND_E_BAD_ARG`）です。

### 3.3 演算子と予約記号

引用の外にある次の並びは、空白がなくても語を区切ります。

| 記号 | 意味 |
|---|---|
| `;` | コマンドを順に実行する |
| `&&` | 直前が成功（`$? = 0`）のときだけ次を実行する |
| `\|\|` | 直前が失敗（`$? ≠ 0`）のときだけ次を実行する |
| `<`、`>`、`>>` | リダイレクト（§6） |
| `2>`、`2>>`、`2>&1` | STDERR のリダイレクト（§6）。`2` が語の先頭にあるときだけ演算子になる（`a2>x` は語 `a2` と `>`） |
| `#` | 語の先頭にあれば、そこから行末までがコメント |
| `\|`、`&`、`(`、`)`、`` ` `` | **予約**。v1 では構文エラー（`FND_E_UNSUPPORTED`、メッセージ `not supported`）。§13 の未決事項を参照 |

## 4. 構文

```text
line      = [ list ] ;
list      = and_or { ";" and_or } [ ";" ] ;
and_or    = command { ( "&&" | "||" ) command } ;
command   = { redirect } word { word | redirect } ;
redirect  = ( "<" | ">" | ">>" | "2>" | "2>>" ) word
          | "2>&1" ;
```

- `&&` と `||` は同じ優先度で、左から結合します。`a && b || c` は「`a` が成功なら `b`。その結果が失敗なら `c`」です。
- 実行しなかったコマンドは `$?` を変えません。
- 空の行とコメントだけの行は何もせず、`$?` も変えません。
- リダイレクトだけでコマンドのない `command` は構文エラーです。
- 構文エラーの行は、一部も実行しません。

## 5. 展開

語は次の順で処理します。

1. **変数展開**（§5.1）。引用の外と `"..."` の中で行う。
2. **ワイルドカード展開**（§5.2）。引用の外に書かれた `*` と `?` を含む語だけが対象。
3. **引用の除去**。

変数の値に含まれる空白、引用、演算子、`*`、`?` は文字として扱います。展開の結果を語に分け直すことはありません。つまり 1 つの語は展開後も 1 つの語です（ワイルドカード展開を除く）。

### 5.1 変数

- 名前は `[A-Za-z_][A-Za-z0-9_]*` で、31 bytes 以下です。ASCII の大文字小文字を区別しません。
- `$NAME` と `${NAME}` は値に置き換わります。未定義の変数は空文字列です。
- `$` の後に名前も `{`、`?`、`#`、数字も続かない場合、`$` はそのままの文字です。

特殊な変数は次のとおりです。いずれも `set` では変更できません。

| 変数 | 値 |
|---|---|
| `$?` | 直前に実行したコマンドの終了コード（10 進の `i32`）。初期値は 0 |
| `$0` | スクリプトの実行中はスクリプトのパス、それ以外は `shell` |
| `$1`〜`$9` | スクリプトの引数（§8）。それ以外では空 |
| `$#` | スクリプトの引数の数。それ以外では 0 |

既定で定義する変数：

| 変数 | 既定値 | 用途 |
|---|---|---|
| `PATH` | `/bin` | コマンドの検索（§7.1）。`:` で区切る |

変数はシェルの中だけのものです。起動ブロックに環境変数の欄はないため、子プロセスには渡りません。

### 5.2 ワイルドカード

- `*` は 0 文字以上、`?` はちょうど 1 文字（Unicode scalar value）に一致します。
- ワイルドカードを書けるのはパスの最後の成分だけです。それより前の成分にあれば `FND_E_BAD_PATH` です。
- 照合は [FS2 §6](spec_FS2.md) の名前照合（Unicode 16.0.0 full case folding）と同じ規則で行います。DSFS の媒体でも同じです。
- `.` で始まる名前は、パターンの成分も `.` で始まるときだけ一致します。`.` と `..` は一致の対象にしません。
- 一致した名前は FS2 の照合順（folding 後の UTF-8 byte 順）に並べ、ディレクトリ部分を付けた語に置き換えます。
- 一致がなければ、そのコマンドは実行せず、`no match` を表示して `FND_E_NOT_FOUND` にします（パターンを文字のまま渡すことはしない）。
- 一致は 256 件までです。超えた場合は `FND_E_LIMIT` で、コマンドは実行しません。
- ディレクトリを読めない場合（権限、媒体なしなど）は、そのエラーでコマンドを実行しません。

## 6. リダイレクト

| 記法 | 動作 |
|---|---|
| `< path` | `path` を読み取りで開き、STDIN にする |
| `> path` | `path` を作成、または長さ 0 にして書き込みで開き、STDOUT にする |
| `>> path` | `path` を作成、または末尾から追記で開き、STDOUT にする |
| `2> path`、`2>> path` | STDERR に対して `>`、`>>` と同じ |
| `2>&1` | その時点の STDOUT を STDERR にも使う |

- リダイレクトは左から順に処理します。`> a 2>&1` は両方を `a` に向け、`2>&1 > a` は STDERR だけを元の STDOUT に残します。
- 対象の語は §5 で展開します。ワイルドカードの一致がちょうど 1 件でなければエラーです。
- 開くときの権限と作成時の属性は [FS2 §8](spec_FS2.md) に従います。新規ファイルの mode は既定（`0x0034`）です。
- 開けなかった場合、そのコマンドは実行しません。それまでに開いたリダイレクトはすべて閉じます。
- 外部コマンドにも組み込みコマンドにも同じように働きます（例：`ls > list.txt`）。
- 同じファイルを入力と出力の両方に指定しても検査しません（`cat a > a` は `a` を空にしてから読む）。
- コマンドが終わったら、シェルはリダイレクトで開いたハンドルを閉じます。

## 7. コマンドの解決と実行

### 7.1 解決の順序

コマンド名（展開後の最初の語）を次の順で解決します。

1. 名前に `/` を含む場合は、そのパスのファイルを使う（相対パスは cwd から）。拡張子は補わない。
2. 組み込みコマンド（§10）の名前に、ASCII の大文字小文字を区別せずに一致すれば、それを実行する。
3. `PATH` の各ディレクトリを左から順に調べ、`<dir>/<name>.wax`、`<dir>/<name>.fsh` の順に、最初に見つかったものを使う。`<name>` がすでに `.wax` か `.fsh` で終わっていれば、拡張子は補わない。
4. 見つからなければ `command not found` を表示し、`$?` を `FND_E_NOT_FOUND` にする。

- 空の要素と、絶対パスでない要素は `PATH` から無視します。
- 組み込みコマンドと同じ名前の外部コマンドは、パスで指定すれば実行できます（例：`/bin/ls.wax`）。
- 見つかったファイルの種類は拡張子で決めます。`.wax` は外部プログラム（§7.2）、`.fsh` はスクリプト（§8）です。手順 1 でそれ以外の拡張子なら `FND_E_FORMAT` です。
- ファイルを実行するには、FS2 の X 権限が必要です（[FS2 §8](spec_FS2.md)）。DSFS の媒体のファイルは既定で X を持たないため、`/dd/<n>` の DSFS から直接は実行できません。

### 7.2 外部プログラムの実行

1. ファイル全体をシェルのヒープ（`mem_grow`）に読み込みます。大きさの上限は 1 MiB（`SHELL_IMAGE_MAX`）で、超える場合は `image too large` と `FND_E_LIMIT` になります。
2. 起動ブロックを作ります（§7.3）。
3. `proc_spawn` を次の値で呼びます。
   - `priority = 2`（APP）、`caps = 0`、MMIO の付与なし
   - `name` は、パスの最後の成分から `.wax` を除いたものの先頭 15 bytes
   - `handles` は §7.3 の役割表の順
4. 読み込んだイメージを解放します（成功、失敗にかかわらず）。
5. 起動に失敗した場合は、エラーを表示して `$?` をその値にします。`FND_E_ADDRESS_CONFLICT` には `slot in use` と表示します。
6. 成功したら `wait(h, FND_FOREVER, &code)` で終了を待ち、PROCESS ハンドルを閉じて、`$?` を終了コードにします。fault で終わったプロセスの終了コードは CAUSE 値（負）です。

v1 のシェルは前面の 1 つのプロセスだけを実行します。バックグラウンド実行はありません。

WAX v3 の WAL を必要とするプログラムで、どのライブラリ一覧を `proc_spawn` に渡すかは [Foundation §9.5](spec_Foundation.md) で未決です。決まるまで、シェルは v3 の依存を持つ WAX を起動できません（カーネルが返すエラーをそのまま表示する）。

### 7.3 子プロセスの起動ブロック

| 項目 | 値 |
|---|---|
| argv[0] | 解決したファイルの絶対パス |
| argv[1..] | 展開後の残りの語（リダイレクトの部分は除く） |
| cwd | シェルの現在の cwd（絶対パス） |
| 役割表 | 1 `STDIN`、2 `STDOUT`、3 `STDERR`、4 `FS`、5 `CONSOLE`（この順に `handles` へ並べ、子では 1〜5 番になる） |

- `STDIN`、`STDOUT`、`STDERR` は、リダイレクト後のストリームです。リダイレクトがなければシェル自身が受け取ったものを渡します。
- `FS` は、子のための新しい fs セッションの CHANNEL です（§12 の要求 R3）。シェル自身の `FS` を共有してはなりません。共有すると、cwd と開いたファイルが同じセッションに混ざります。
- `CONSOLE` は、シェルが受け取ったものを渡します。
- 起動ブロック全体は 4096 bytes 以下でなければなりません（[Foundation §9.2](spec_Foundation.md)）。超える場合は `argument list too long` と `FND_E_LIMIT` で、起動しません。

## 8. スクリプト

- スクリプトは拡張子 `.fsh` の UTF-8 テキストで、1 行ずつ §3〜§7 の規則で実行します。行の上限、コメント、空行の扱いは対話入力と同じです。
- スクリプトは**呼び出したシェルの中で**実行します。新しいプロセスは作りません。
- 変数はシェル全体で共有します。スクリプトの中の `set` は、終了後も残ります。
- `$0`〜`$9` と `$#` は、スクリプトの開始時に設定し、終了時に呼び出し前の値に戻します。引数が 9 個を超えた場合、10 個目以降は `$#` に数えますが、参照する手段はありません。
- cwd は共有します。スクリプトの中の `cd` は、終了後も残ります。
- 途中のコマンドが失敗しても、次の行へ進みます。止めたい場合は `cmd || exit $?` と書きます。
- スクリプトの終了コードは、`exit` で指定した値か、最後に実行したコマンドの `$?` です。
- スクリプトの中の `exit` は、そのスクリプトだけを終わらせます。シェルを終わらせるのは、対話入力で実行した `exit` と、`-c` またはスクリプトモードの最上位の `exit` だけです。
- スクリプトの入れ子は 8 段までです。超えた場合は `FND_E_LIMIT` で、そのスクリプトを実行しません。
- スクリプトのファイルは、開始時に全体を読み込みます（上限 64 KiB、超えると `FND_E_LIMIT`）。実行中にファイルを書き換えても、実行中の内容は変わりません。
- スクリプトにもリダイレクトを付けられます。その場合、スクリプト内の各コマンドの既定のストリームが置き換わります。

## 9. 対話入力

### 9.1 プロンプト

プロンプトは cwd の絶対パスと `> ` です（例：`/home> `）。STDOUT に出力します。

### 9.2 行編集

シェルは CONSOLE からキーを 1 つずつ受け取り、自分で行を編集します（§12 の要求 R4）。

| キー | 動作 |
|---|---|
| 文字 | カーソル位置に挿入する |
| ←、→、Home、End | カーソルを動かす |
| Backspace、Delete | カーソルの前、後の 1 文字（scalar value）を消す |
| ↑、↓ | 履歴をたどる。履歴は 16 行で、直前と同じ行と空行は記録しない |
| Enter | 行を確定して実行する |
| Ctrl+C | 入力中の行を捨て、`^C` と改行を出して新しいプロンプトを出す。`$?` は変えない |

- 行の上限（1023 bytes）を超える入力は受け付けません（ベルなどの通知はコンソールの仕様に任せる）。
- 補完はありません。

### 9.3 中断（Ctrl+C）

- コマンドの実行中に Ctrl+C が押されたら、シェルは中断します。中断の通知はコンソールから受け取ります（§12 の要求 R5）。シェルは通知を待つ専用のスレッドを `thread_create` で 1 つ持ちます。
- 外部プログラムの実行中なら、`proc_kill` でそのプロセスを終了させます。`$?` は `FND_E_KILLED` です。
- 組み込みコマンドの実行中なら、そのコマンドを途中で止めます（開いたファイルは閉じる）。`$?` は `FND_E_KILLED` です。
- スクリプトの実行中なら、入れ子のすべてのスクリプトを止めます。対話モードならプロンプトへ戻り、`-c` やスクリプトモードならシェルが `FND_E_KILLED` で終了します。
- 中断したら `^C` と改行を STDERR に出します。

## 10. 組み込みコマンド

- 組み込みコマンドの終了コードは、成功で 0、失敗で負のエラーコードです。
- 複数の対象を取るコマンド（`rm a b c` など）は、失敗した対象があっても残りを処理します。`$?` は最初に起きたエラーです。
- 不明なオプションと引数の数の誤りは、使い方を STDERR に出して `FND_E_BAD_ARG` にします。
- 出力はリダイレクト後の STDOUT、エラーは STDERR に書きます。

| コマンド | 書式 | 動作 |
|---|---|---|
| `cd` | `cd [path]` | cwd を変える。引数がなければ `/` にする（v1 にはホームディレクトリがない） |
| `pwd` | `pwd` | 現在の cwd（絶対パス）を表示する |
| `ls` | `ls [-l] [path...]` | ディレクトリの内容を表示する（§10.1）。`path` がファイルならそのファイルだけ。省略時は cwd |
| `cat` | `cat path...` | ファイルの内容をそのまま STDOUT に書く。ディレクトリは `FND_E_IS_DIR` 相当のエラー |
| `cp` | `cp [-f] src... dst` | ファイルを複製する（§10.2） |
| `rm` | `rm path...` | ファイルを削除する。ディレクトリは削除しない。確認はしない |
| `mv` | `mv old new` | 名前を変える、または移動する。同じ mount の中だけ（§10.2） |
| `mkdir` | `mkdir path...` | ディレクトリを作る（mode は既定 `0x003D`）。途中のディレクトリは作らない |
| `rmdir` | `rmdir path...` | 空のディレクトリを削除する |
| `clear` | `clear` | 画面を消す（CONSOLE を使う。STDOUT がリダイレクトされていても画面を消す） |
| `echo` | `echo [word...]` | 語を空白 1 つでつなぎ、改行を付けて書く。引数がなければ改行だけ |
| `set` | `set`／`set NAME`／`set NAME=value` | 引数なしで全変数を名前順に表示する。`NAME` だけならその値を表示する（未定義は `FND_E_NOT_FOUND`）。`NAME=value` で設定し、`value` が空なら削除する |
| `uname` | `uname` | OS の版 `Foundation OS (kernel ABI <major>.<minor>)`（`sys_info` sel 0）と `Foundation shell 1.0` を 1 行ずつ表示する |
| `free` | `free` | RAM 容量と空き容量を KiB で表示する（`sys_info` sel 0） |
| `ps` | `ps` | プロセス一覧を表示する（`sys_info` sel 1）。列は PID、PARENT、STATE、PRIO、MEM、NAME |
| `help` | `help [command]` | 組み込みコマンドの一覧と 1 行説明、または指定したコマンドの書式を表示する |
| `exit` | `exit [code]` | §2.3、§8。`code` は 10 進の `i32` |

- `set NAME=value` は 1 つの語として受け取ります。`=` の前後に空白を入れてはなりません。空白を含む値は `set "MSG=hello world"` のように引用します。
- エラーメッセージ（§11.1）の `<command>` には、表の小文字の名前を使います。
- DOS の名前（`DIR`、`TYPE`、`COPY` など）の別名は設けません。必要なら外部コマンドかスクリプトで用意します。
- 実装案にあった `KILL`（UNIX 風には `kill`）は v1 では設けません。現行のカーネル ABI では `proc_kill` に PROCESS ハンドルが必要で、シェルは他のプロセスのハンドルを持てないためです（§13）。

### 10.1 `ls` の出力

既定では 1 件 1 行で名前だけを出します。`-l` を付けると、次の形式で出します。

```text
2026-10-22 13:05  <DIR>       docs
2026-10-21 09:12        1234  readme.txt
```

- 日時は FS2 の時刻（UNIX 秒）を UTC として `YYYY-MM-DD HH:MM` で表示します。
- 大きさは 10 進の byte 数です。名前は保存されている形のまま表示します。
- 並び順は FS2 の照合順です。`.` で始まる名前も表示します。
- `-l` では、最後に `<n> file(s), <m> dir(s)` を 1 行出します。

### 10.2 `cp` と `mv`

- `cp` の `src` が 2 つ以上（ワイルドカードの展開を含む）なら、`dst` は既存のディレクトリでなければなりません。`dst` がディレクトリなら、各 `src` の最後の成分の名前で、その中に作ります。
- 複製先がすでにあれば `FND_E_EXISTS` で、その対象は飛ばします。`-f` を付けると上書きします。
- ディレクトリは複製しません（`src` がディレクトリならエラー）。
- 複製先の UID、mode、時刻は FS2 の作成規則に従います（元の属性は引き継がない）。DSFS から FS2 への複製もこの規則です。
- 同じファイルへの複製はエラーです。
- `mv` は FS2 の rename です。別の mount への移動はせず、エラーにします（`cp` と `rm` を使う）。`new` がすでにあれば `FND_E_EXISTS` です。

## 11. メッセージと上限

### 11.1 エラーメッセージ

エラーは次の形式で STDERR に 1 行出します。

```text
<command>: <target>: <message> (<code>)
<command>: <message> (<code>)
```

例：`cat: notes.txt: not found (-10)`、`foo: command not found (-10)`。

カーネルのエラーコード（[Foundation §4](spec_Foundation.md)）のメッセージは次のとおりです。API のエラー（-64〜-255）のメッセージは [API 仕様 §11.9](spec_Foundation_API.md) で定めます。表にない値は `error` とします。

| コード | メッセージ | コード | メッセージ |
|---|---|---|---|
| `FND_E_BAD_ARG` | `invalid argument` | `FND_E_FORMAT` | `bad format` |
| `FND_E_BAD_HANDLE` | `bad handle` | `FND_E_UNSUPPORTED` | `not supported` |
| `FND_E_ACCESS` | `access denied` | `FND_E_ADDRESS_CONFLICT` | `slot in use` |
| `FND_E_NO_MEMORY` | `out of memory` | `FND_E_REGION_LIMIT` | `too many regions` |
| `FND_E_LIMIT` | `limit exceeded` | `FND_E_IO` | `I/O error` |
| `FND_E_PEER_GONE` | `service gone` | `FND_E_NO_MEDIA` | `no media` |
| `FND_E_NOT_FOUND` | `not found` | `FND_E_READ_ONLY` | `read-only` |
| `FND_E_EXISTS` | `already exists` | `FND_E_BUSY` | `busy` |
| `FND_E_KILLED` | `interrupted` | `FND_E_DEPENDENCY` | `missing dependency` |

外部プログラムが 0 以外の終了コードで終わった場合、シェルはメッセージを出しません（`$?` だけを設定する）。fault（`-256` 以下）で終わった場合だけ、`<name>: fault <CAUSE の 16 進> at <EPC の 16 進>` を出します。EPC は `sys_info` sel 1 の `fault_epc` から読みます。

### 11.2 上限

| 項目 | 上限 |
|---|---|
| 1 行 | 1023 bytes |
| 1 コマンドの語 | 64 個（展開後） |
| ワイルドカードの一致 | 256 件 |
| 変数 | 64 個。名前 31 bytes、値 1023 bytes |
| 子の起動ブロック | 4096 bytes |
| 外部プログラムのイメージ | 1 MiB |
| スクリプトのファイル | 64 KiB |
| スクリプトの入れ子 | 8 段 |
| 履歴 | 16 行 |

## 12. libfnd と各サービスへの要求

シェルは次の機能を必要とします。[API 仕様](spec_Foundation_API.md) がこれらを定めます（右端の列）。

| 要求 | 内容 | API 仕様 |
|---|---|---|
| R1 ストリーム | コンソール、ファイル、`/dev` のノードが、同じ読み書きのプロトコル（read、write、close）を話す CHANNEL である。子は STDIN などの種類を区別せずに使える | §5 |
| R2 ストリームの委譲 | fs で開いたファイルのストリームを、IPC のハンドル転送と `proc_spawn` の `handles` で別プロセスへ渡せる。渡した先でも、開いたときに許可した操作だけができる（[FS2 §8・§11.2](spec_FS2.md)） | §4.2 |
| R3 fs セッションの発行 | シェルの fs セッションから、同じ資格情報を持つ新しいセッションの CHANNEL を作れる（子の `FS` 役割に使う） | §6.3 `FS_SESSION_NEW` |
| R4 キー入力 | CONSOLE から、行編集に必要なキー（文字、矢印、Home、End、Backspace、Delete、Enter）を 1 つずつ読める | §8.3 `CON_READ_KEY` |
| R5 中断の通知 | Ctrl+C を入力の文字として子に渡さず、セッションの持ち主（シェル）へ通知として届ける。シェルの別スレッドがそれを待てる | §8.4 |
| R6 名前照合 | FS2 §6 と同じ照合をする関数（`*` と `?` のパターン照合を含む）を libfnd が提供する | §11.7 |
| R7 ディレクトリ列挙 | 名前、種類、大きさ、更新時刻を返す列挙（FS2 §11.2 の readdir 相当） | §7、§10.2 |
| R8 画面消去 | CONSOLE に画面消去の操作がある | §8.3 `CON_CLEAR` |

## 14. 適合確認（実装時に追加するテスト）

以下は将来の実装に対する要求で、実行済みのテストではありません。

- **字句と構文**：引用（`'`、`"`、`\`）の組み合わせ、閉じていない引用、行末の `\`、予約記号、`2>` の判定、1023 bytes を超える行が、それぞれ §3〜§4 のとおりになる。構文エラーの行は一部も実行されない。
- **条件実行**：`cat missing && a || b`（`missing` は存在しない）で `a` を実行せず `b` を実行し、実行しなかったコマンドは `$?` を変えない。
- **展開**：変数の値の空白や `*` が分割・展開されない。ワイルドカードが大小文字を区別せずに一致し、一致なしで実行されず、257 件で `FND_E_LIMIT` になる。
- **解決**：組み込みコマンドが `PATH` より優先され、`.wax` が `.fsh` より優先され、X 権限のないファイルは実行されない。
- **リダイレクト**：`> a 2>&1` と `2>&1 > a` の違い、開けない対象で実行されないこと、組み込みコマンドの出力の書き込み、終了後にハンドルが閉じられることを確認する。
- **外部プログラム**：起動ブロックの argv、cwd、役割表が §7.3 のとおりで、終了コードと fault が `$?` に入る。起動を繰り返してもシェルのヒープとハンドルが漏れない。
- **スクリプト**：変数と cwd の共有、`$1`〜`$9` の復元、`exit` がスクリプトだけを終わらせること、9 段目の入れ子の拒否を確認する。
- **中断**：外部プログラム、組み込みコマンド、入れ子のスクリプトの実行中に Ctrl+C を押すと、§9.3 のとおりに止まり、`$?` が `FND_E_KILLED` になる。
