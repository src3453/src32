# sol (Stack Oriented Language) 仕様書

sol (Stack Oriented Language) は、スタック指向のプログラミング言語であり、SRC32アセンブリにコンパイルされる。
名称は小文字の "sol" で表記される。

スタックには32ビットの符号付き(リターンスタックは符号なし)数値が入る。データスタックとリターンスタックを持つ。 
文はスペースで区切られていて、左から解釈される。
ほとんどのオペレーターは短い (基本的に5文字以内) アルファベットで記述する。 
記号類は特殊な修飾子などに使われる。 
これらの文は最終的にSRC32のアセンブリにコンパイルされる。

# スタック
スタックは、LIFO (Last In First Out) のデータ構造であり、最後にプッシュされた値が最初にポップされる。スタックは、データスタックとリターンスタックの2つの部分からなる。
# 関数
関数は `fn name (arg1 arg2 ...) :` で始まり、関数名と引数名を `(...)` 内に指定する。関数の本体は `;` で終了する。

この仕様では、関数呼び出しのための呼び出し規約（calling convention）とスタックフレームのレイアウトを定める。コンパイラはこの規約に従ってコードを生成し、ランタイム（VM/アセンブリ）はそれを実行する。

重要な前提:
- データスタックは下方向（アドレスが小さくなる方向）に伸びるものとする（push は R28 を 4 バイト減算して書き込む）。R28 は実行時スタックポインタを指す。
- リターンスタックは別に存在し、呼び出し先アドレスの保存に用いる。

## 呼び出し規約

ソルの関数呼び出しは、データスタックを引数受け渡しと式評価に使う。規約は次の通りとする。

1. 呼び出し側（caller）は、引数を左から右の順でデータスタックに積む。つまり `fn f (a b)` に対しては `a` を先に push し、その後に `b` を push する。
2. 呼び出し命令 `call @label` は、データスタック最上位から関数の引数個数ぶんを消費し、それらをその関数の引数として扱う。関数の下に残っている既存のスタック値は保持される。
3. 呼び出し時、ランタイムは関数用のフレームを確保し、引数とローカル変数はそのフレーム内の固定オフセットでアクセスされる。
4. 関数本体は、戻り値をデータスタックのトップに 1 個だけ残して `ret` を実行する。`ret` はフレームを解放し、呼び出し元へ戻る。
5. 戻り値を返さない関数は `retn` を使う。`retn` はフレームを解放し、戻り先に復帰するが、データスタック上の戻り値は残さない。

この規約では、関数呼び出しは「スタックの先頭に対する局所的な操作」であり、呼び出し前にスタック下位へ積まれていた値は関数終了後も保持される。したがって、関数呼び出しはスタック全体を丸ごと置き換えるのではなく、引数部分だけを消費して 0 個または 1 個の結果を返す。

## スタックフレームのレイアウト

フレームはコンパイル時に必要なローカル変数数（N_locals）と引数数（N_args）が分かればサイズが決定できる。

- フレームは 4 バイト単位で整列される。
- フレーム確保時の R28 の変化（スタックが下方向に成長するため）:
  - R28 := R28 - 4 * (N_locals + N_args)
- フレーム内のオフセット（R28 がフレームのベースを指す、すなわち最も低いアドレス）:
  - ローカル変数 i (0-based): address = R28 + 4 * i
  - local 0 は R28 + 0、local 1 は R28 + 4、... の位置に置かれる。
  - 引数 j (0-based, 左から右の順に arg0, arg1, ...): address = R28 + 4 * (N_locals + j)
  - arg0 はローカル領域の直後に置かれる。

この設計により、同じ関数内ではローカル変数と引数を固定オフセットでアクセスできる。ネストした呼び出しや再帰呼び出しの際でも、各呼び出しは独立したフレームを持つ。

## 変数参照と代入のコンパイル方針

- 変数名を式で使う（例: `a`）ときは、その変数の値をスタックにプッシュするコードが生成される。具体的には、フレーム内の対応するアドレスを計算して `ld` を行う。
- `>varname` のような代入は、スタックのトップの値を pop して変数のアドレスに `st` するコードにコンパイルされる。

例: 変数 `x` を読み出す場合、生成される擬似シーケンスは次のような形になる（アセンブリは実装依存）:
- (push address of x) ; 例: R28 + offset を計算してアドレスをスタックに置く
- `ld`                ; そのアドレスから値をロードして値をスタックに置く

代入 `>x` の生成:
- (push address of x)
- (push value)
- `st`                ; アドレスと値を使って書き込みを行う

## 呼び出し命令と戻り命令

- 呼び出し: `call @label`
  - 作用:
    1. リターンスタックへ戻りアドレスをプッシュする。
    2. 関数が必要とする引数個数ぶんをデータスタック最上位から消費する。
    3. フレーム領域を確保し、引数とローカル変数のアクセス先を決める。
    4. ジャンプして関数本体を開始する。
- 戻り（戻り値あり）: `ret`
  - 作用:
    1. 関数は戻り値をデータスタックのトップに 1 個だけ残しておく。
    2. フレームを解放する。
    3. リターンスタックから戻りアドレスを取り出してジャンプする。
    4. 呼び出し前にデータスタック下位にあった値は保持する。
- 戻り（戻り値なし）: `retn`
  - 作用:
    1. 関数は戻り値を返さない。
    2. フレームを解放してリターン先にジャンプする。
    3. 呼び出し前にデータスタック下位にあった値は保持し、callee が積んだ値は破棄する。

補足:
- 関数本体が明示的な `ret` または `retn` を含まずに終了した場合、コンパイラは関数の終端に暗黙の `retn` を挿入する（戻り値なしでの復帰を行う）。
- 再帰呼び出しやネストされた呼び出しに対応するため、フレームサイズは呼び出しごとに独立であること。

例:
```
fn add_two_numbers (a b) :
    local sum
    a b add >sum   # sum = a + b
    sum            # 戻り値として sum をスタックトップに残す
;

# 呼び出し側
1 2 add_two_numbers
prn  # 出力: 3
```

# コンパイラ・ディレクティブ
ディレクティブの先頭には`!`が付く。ディレクティブは、コンパイラに対して特定の指示を与えるために使用される。
| ディレクティブ | 説明 |
| --- | --- |
| `!include "filename"` | 指定されたファイルをインクルードする |
| `!define MACRO_NAME value` | マクロを定義する |
| `!undef MACRO_NAME` | マクロを未定義にする |
| `!const CONST_NAME value` | 定数を定義する |
| `!var VAR_NAME [value]` | 変数を定義する。初期値は省略可能で、省略時は 0 で初期化される。|
| `!end` | 現在のディレクティブのブロックを終了する |
| `!required_stack_size size` | スタックの必要サイズを指定する（実装のスタックサイズが指定されたサイズより小さい場合、プログラムはランタイムエラーで終了する） |
| `!required_return_stack_size size` | リターンスタックの必要サイズを指定する（実装のリターンスタックサイズが指定されたサイズより小さい場合、プログラムはランタイムエラーで終了する） |
| `!force_stack_size size` | スタックの強制サイズを指定する (ランタイムは使用可能なスタックサイズを強制的にこれに設定する; 実装のスタックサイズが指定されたサイズより小さい場合、プログラムはランタイムエラーで終了する) |
| `!force_return_stack_size size` | リターンスタックの強制サイズを指定する（ランタイムは使用可能なリターンスタックサイズを強制的にこれに設定する; 実装のリターンスタックサイズが指定されたサイズより小さい場合、プログラムはランタイムエラーで終了する） |
| `!asm` | `!end`までの以降の行をアセンブリコードとして扱う |

## `!asm`
`!asm`ディレクティブは、以降の行をアセンブリコードとして扱うことを指定する。`!end`ディレクティブが現れるまで、すべての行はアセンブリコードとして解釈される。
コンパイラは、`!asm`ディレクティブの後に続く行をそのままアセンブリコードとして出力する。これにより、特定のアセンブリ命令を直接使用することができる。
例:
```
!asm
; ここからアセンブリコード
LDI R1, 0x1234 ; Load VDP Mode Register Address
LDI R2, 0x01 ; Load value to set VDP to text mode
STB [R1], R2 ; Set VDP to text mode
!end
```

# コンパイラオプション

- グローバル変数の割当ベースアドレスを指定するにはコンパイラの `--var-base` オプションを使用する（デフォルト: 0x00100000）。
- 実行時スタック(R28)の初期位置を指定するにはコンパイラの `--stack-top` オプションを使用する（デフォルト: 0x000FFFFC）。


# 関数
関数は `fn name (arg1 arg2 ...) :` で始まり、関数名と引数名を `(...)` 内に指定する。関数の本体は `;` で終了する。

この仕様では、関数呼び出しのための呼び出し規約（calling convention）とスタックフレームのレイアウトを定める。コンパイラはこの規約に従ってコードを生成し、ランタイム（VM/アセンブリ）はそれを実行する。

重要な前提:
- データスタックは下方向（アドレスが小さくなる方向）に伸びるものとする（push は R28 を 4 バイト減算して書き込む）。R28 は実行時スタックポインタを指す。
- リターンスタックは別に存在し、呼び出し先アドレスの保存に用いる。

呼び出しの高レベルな動作:
1. 呼び出し側（caller）は引数をデータスタックに左から右の順（左の引数を先に push）で準備する。
2. 呼び出し命令 `call @label`（コンパイラが生成する）を実行すると、ランタイムは戻り先アドレスをリターンスタックに保存し、関数用のフレーム領域をスタック上に確保し、制御を関数エントリに移す。
3. 関数内では引数とローカル変数はスタックフレーム内の固定オフセットに配置され、変数名はそのオフセットにマップされる。
4. 関数は戻り値をデータスタックのトップに置いて `ret` を実行する。`ret` はフレームを解放し、リターンスタックから戻り先を取り出してジャンプする。

スタックフレームのレイアウト
- フレームはコンパイル時に必要なローカル変数数（N_locals）と引数数（N_args）が分かればサイズが決定できる。
- フレームは 4 バイト単位で整列される。
- フレーム確保時の R28 の変化（スタックが下方向に成長するため）:
  R28 := R28 - 4 * (N_locals + N_args)

フレーム内のオフセット（R28 がフレームのベースを指す、すなわち最も低いアドレス）:
- ローカル変数 i (0-based): address = R28 + 4 * i
  - local 0 は R28 + 0、local 1 は R28 + 4、... の位置に置かれる。
- 引数 j (0-based, 左から右の順に arg0, arg1, ...): address = R28 + 4 * (N_locals + j)
  - arg0 はローカル領域の直後に置かれる。

この設計により、同じ関数内ではローカル変数と引数を固定オフセットでアクセスできる。ネストした呼び出しや再帰呼び出しの際でも、各呼び出しは独立したフレームを持つ。

変数参照と代入のコンパイル方針
- 変数名を式で使う（例: `a`）ときは、その変数の値をスタックにプッシュするコードが生成される。具体的には、フレーム内の対応するアドレスを計算して `ld` を行う。
- `>varname` のような代入は、スタックのトップの値を pop して変数のアドレスに `st` するコードにコンパイルされる。

例: 変数 `x` を読み出す場合、生成される擬似シーケンスは次のような形になる（アセンブリは実装依存）:
- (push address of x) ; 例: R28 + offset を計算してアドレスをスタックに置く
- `ld`                ; そのアドレスから値をロードして値をスタックに置く

代入 `>x` の生成:
- (push address of x)
- (push value)
- `st`                ; アドレスと値を使って書き込みを行う

呼び出し命令と戻り命令
- 呼び出し: `call @label`
  - 作用:
    1. リターンスタックへ戻りアドレスをプッシュ（コンパイル時に決めた戻り番地を使う）
    2. R28 を `R28 - 4 * (N_locals + N_args)` してフレーム領域を確保
    3. スタックに置かれていた引数（caller により push 済み）をフレーム内の引数スロットにコピーするか、コンパイラが最初から引数をフレーム位置に push するように生成している（詳細はコンパイラ実装に依存するが、結果として関数エントリ時点で引数は前述のオフセットに存在する）
    4. ジャンプして関数本体を開始する
- 戻り（戻り値あり）: `ret`
  - 作用:
    1. （関数が戻り値をデータスタックのトップに置いている前提）
    2. R28 を `R28 + 4 * (N_locals + N_args)` してフレームを解放
    3. リターンスタックから戻りアドレスを取り出してジャンプ
- 戻り（戻り値なし）: `retn`
  - 作用:
    1. 関数は戻り値を返さず、単に呼び出し元へ戻る
    2. フレームを解放して（R28 を `R28 + 4 * (N_locals + N_args)`）、リターン先にジャンプする
    3. 実装は、呼び出し時に記録したデータスタックの高さへデータスタックを切り詰め（callee が積んだ値を破棄）して呼び出し元のスタック状態へ復元する

補足:
- 関数本体が明示的な `ret` または `retn` を含まずに終了した場合、コンパイラは関数の終端に暗黙の `retn` を挿入する（戻り値なしでの復帰を行う）。

実装上の注意点
- 関数エントリでの引数の受け渡しはコンパイラが一貫して扱うこと。最も単純な方式は、呼び出し前に caller が引数をデータスタック上に push し、`call` によりその領域がそのままフレームの引数スロットとして使われるようコンパイラがレイアウトを合わせる方法である（追加コピーを不要にする）。別方式として `call` が引数をフレーム領域へコピーしても良い。
- `ret` は必ず関数が果たすべき後片付け（必要があればローカル領域の破棄やリソース解放）を済ませた後に実行されるべきである。
- 再帰呼び出しやネストされた呼び出しに対応するために、フレームサイズは呼び出しごとに独立であること。

例:
```
fn add_two_numbers (a b) :
    local sum
    a b add >sum   # sum = a + b
    sum            # 戻り値として sum をスタックトップに残す
;

# 呼び出し側
1 2 call add_two_numbers  # またはコンパイラは `1 2 add_two_numbers` を `1 2 call add_two_numbers` に展開してもよい
prn  # 出力: 3
```

# 定数・変数
定数は、`!const` ディレクティブを使用して定義される。定数は、プログラムの実行中に変更することはできない。
変数は、`!var` ディレクティブを使用して定義される。変数は、プログラムの実行中に変更することができる。
変数への値の格納は、`>` 接頭辞を使用して行う。
例:
```
!const PI 3.14159
!var num 3
PI prn
num PI mul >num  # numにPIを掛けた値を格納
num prn  # 出力: 9.42477
```

# ローカル変数
ローカル変数は、関数の本体内で定義され、関数の呼び出しが終了すると破棄される。ローカル変数は、関数の引数として渡される値を格納するために使用される。
ローカル変数は、関数の本体内で `local` キーワードを使用して宣言される。`local var_name initial_value` の形式で、初期値を指定することもできる。初期値が指定されない場合は、ローカル変数は`0`で初期化される。
ローカル変数は、関数の本体内でのみ有効であり、関数の外部からアクセスすることはできない。
ローカル変数への値の格納は、`>` 接頭辞を使用して行う。
例:
```
fn example_function (a b) :
    local c  # ローカル変数cを定義
    a b add >c  # aとbを加算し、結果をローカル変数cに格納
    c 2 mul  # ローカル変数cの値を2倍する
;
1 2 example_function prn  # 出力: 6
```

# 変数スコープ

名前解決の優先順位:

1. ローカル変数
2. 関数引数
3. グローバル変数
4. 定数
5. 未定義エラー

同一スコープ内で同名変数を定義することは禁止する。
例:
```
fn example_function (a b) :
    local a  # エラー: 同一スコープ内で同名変数を定義することは禁止されている
    a b add
;
```    

# コンパイラ、ツールチェイン
solは`solc`というコンパイラを使用して、SRC32のアセンブリにコンパイルされる。`solc`は、ソースコードを解析し、構文エラーや型エラーを検出する。エラーが検出された場合、コンパイルは中止され、エラーメッセージが表示される。
