# CPT32 BIOS 仕様（起動順序とブート引き渡し）

本仕様は C 版 BIOS（[`bios/main.c`](../bios/main.c)、ROM 生成物 `assets/bios.rom`）がリセット後に行う処理と、次段のプログラムへ制御を渡すときの外部契約を定める。ROM の配置・config 指定は [spec.md §2.11](spec.md) を参照。旧 sol 版 BIOS（`sol/bios.sol`）は POST 後に常に `0x00000000` へ分岐するだけで、本仕様のブートローダー機能を持たない。

## 1. 処理の流れ

1. POST: 常にマップされている標準デバイスだけを調べて結果を PCG 40 桁表示へ出す（UART・タイマ/RTC・拡張カード窓は調べない）。
2. POST 表示保持: IRQ0（ホストフレームループの VSync）を 120 回待つ。CPU サイクル数による待ちは使わない。
3. ブート: §2 の順に起動デバイスを試し、最初に起動できたものへ §3 の契約で分岐する。

## 2. 起動順序

| 順 | デバイス | 起動条件 | R1（起動デバイス） |
|---:|---|---|---|
| 1 | RAM `0x00000000` | 先頭 32-bit word が 0 以外 | `0xFFFFFFFF` |
| 2 | ROM | 予約。現バージョンは未実装で常にスキップ | — |
| 3–6 | IDC dd0, dd1, dd2, dd3 | §2.2 のブートセクタ検査に合格 | drive 番号 `0`–`3` |

### 2.1 RAM

ホスト（エミュレータ・testbench・package の `entrypoint`）が raw プログラムを RAM 先頭へロード済みなら、その先頭 word は 0 以外になる。BIOS はこれを「RAM に起動可能なプログラムがある」とみなし、内容を検査せずに分岐する。先頭 word が `0x00000000` のプログラムは RAM 起動の対象にならない（RAM 起動させたいプログラムは先頭命令を `NOP` 以外にする）。

### 2.2 IDC ブートセクタ

各 drive について次を順に行う。いずれかで失敗した drive は飛ばして次の drive へ進む。

1. `IDENTIFY` に失敗（未接続・媒体なし）なら「no media」。
2. LBA 0 の 1 sector（512 bytes）を DMAC ch0 で RAM `0x00000000..0x000001FF` へ `READ` する。DMA/IDC エラーなら「read error」とエラーコードを表示する。
3. RAM `0x000001FE` = `0x55`、`0x000001FF` = `0xAA`（[DSFS](spec_DSFS.md) のブートセクタ署名と同じ）でなければ「no boot signature」。

2 または 3 で失敗した場合、BIOS は `0x00000000..0x000001FF` を 0 で消去してから次へ進む（失敗した読込みが次回の RAM 起動判定に残らないようにする）。全 drive が失敗したら「no bootable device」を表示し、全 IRQ を無効化して `HALT` で停止する。

ブートセクタはファイルシステムを問わない。DSFS 媒体では block 0 のブートコード領域（`0x000`–`0x1FD`）がそのまま実行される。

## 3. 引き渡し契約

BIOS は次の状態でエントリ `0x00000000` へ分岐し、戻らない。

| 項目 | 値 |
|---|---|
| PC | `0x00000000` |
| R1 | 起動デバイス（§2 の表） |
| R28 (SP) | `0x000F0000`（BIOS 作業領域の直下。下方向へ使える） |
| R29 (FP) | 0 |
| その他の汎用レジスタ | 不定 |
| CPU モード | S モード（Extension P のユーザーモードは使わない） |
| IRQC | 全 source を無効化（ENABLE=0）し、PENDING を全 ack 済み |
| IRQ vector | BIOS の dispatcher を指したまま。次段は IRQ を有効にする前に自前の vector を設定すること |
| DMAC ch0 / IDC | IDC 起動では読込み完了後の状態（DONE が立っていることがある）。次段は使用前に DONE/ERROR を W1C でクリアする |
| PCG | BIOS の 40 桁表示のまま |

ブートセクタのコードは 512 bytes のうち署名 2 bytes を除く範囲に収め、署名を命令として実行しないこと。追加のセクタは次段が IDC/DMAC を直接操作して読み込む（BIOS は現時点でディスク I/O サービスを提供しない）。

## 4. メモリ使用

| 範囲 | 用途 |
|---|---|
| `0xFF000000..0xFF00FFFF` | BIOS ROM（コード・定数・書込み可能データの初期値） |
| `0x000F0000..0x000FFFFF` | BIOS 作業領域。書込み可能な静的データ（`0x000F0000` から）とスタック（`0x00100000` から下向き） |
| `0x00000000..0x000001FF` | ブートセクタの読込み先 |
| `0x00F00000`, `0x10300000` | POST の RAM/VRAM 試験 word（値は保存・復元する） |

BIOS 作業領域は POST 中に書き換わるため、RAM 起動するホストロード済みプログラムは `0x000F0000` 未満に収まっていなければならない（それより大きいプログラムは作業領域と重なる部分が壊れる）。作業領域の内容は引き渡し後には意味を持たず、次段が自由に使ってよい。

## 5. ROM の生成

`python bios/build.py` が LLVM/SRC32 ドライバーを `--origin 0xFF000000 --data-origin 0x000F0000 --stack-top 0x00100000` で呼び、`assets/bios.rom` を生成する。`--data-origin` は書込み可能な静的データを RAM に置き、起動時に ROM 内の初期値をコピーしてゼロ初期化領域を消去する（[LLVM/SRC32 README](../tools/llvm-src32/README.md)）。出力は ROM 先頭から始まる raw image で、64 KiB を超えるとエラーになる。手順は [bios/README.md](../bios/README.md) を参照。
