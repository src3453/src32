# SqueezVOX 4 (SQV4) バージョン3仕様

この文書は、SQV4H、SQV4L、SQV4L+ の規範的な SQV4 バージョン3のワイヤ形式、予測器規則、エンコーダー規則を定義します。バージョン3はバージョン1・2からの破壊的変更です。各チャネルフラグメントはフルスケールに正規化され、自身の初期ステップインデックスを持ち、それ以前のフラグメントなしに復号できます。このため、デコーダーはストリームの任意のフラグメント境界から復号を始められます。新しいエンコーダーはバージョン3を書き込まなければなりません。バージョン1・2は、古いファイルを再生し続けるデコーダーのために[付録 A](#付録-a-バージョン1と2)に要約します。

特に明記しない限り、複数バイト整数は符号なしリトルエンディアンです。PCM 入出力は符号付き16ビットのインターリーブサンプルです。デコーダーは以下に定める不正または非正規のファイルを拒否しなければなりません。エンコーダーはここで定義する形式を厳密に出力しなければなりません。

SQV4 バージョン3は SGU v3 世代（`doc/spec_SGU.md` §8）に属します。SGU v3 のコアと 34SI22（`doc/spec_34SI22.md`）はバージョン3だけを再生し、SGU v1、v2、v2.1 はバージョン1・2だけを再生します。チップリビジョンは変わりません。

## ファイル形式

固定ヘッダーは16バイトです:

| オフセット | サイズ | 意味 |
| --- | ---: | --- |
| 0 | 4 | ASCII `SQV4` |
| 4 | 1 | バージョン: `3` |
| 5 | 1 | バリアント: `0` = H, `1` = L, `2` = L+ |
| 6 | 1 | チャネル数: `1` モノラルまたは `2` ステレオ |
| 7 | 1 | 予約済み、0でなければならない |
| 8 | 4 | サンプルレート (Hz)、0以外でなければならない |
| 12 | 4 | チャネルあたりのサンプル数 |

空ストリームのサンプル数は0で、ヘッダーのみで構成されます。宣言されたサンプルレートはメタデータであり、デコード時にリサンプリングは行いません。

ペイロードは、チャネルあたり63サンプルの時間順フラグメントで構成されます。各フラグメントでは、チャネルは昇順に並びます。チャネルあたり `n` サンプルの場合、チャネルあたりのフラグメント数は `f = ceil(n/63)`（`n = 0` なら0）で、最後のフラグメントは `n - 63*(f-1)` サンプルを持ちます。

## チャネルフラグメント

| オフセット | サイズ | フィールド |
| --- | ---: | --- |
| 0 | 1 | Volume: 線形ゲイン `0..255` |
| 1 | 1 | Index: 初期ステップインデックス `0..88` |
| 2 | 32 (H) / 24 (L, L+) | Codes: パックされた63個のコード |

H のコードは4ビット、L/L+ のコードは3ビットです。コードは最下位ビット優先でパックされます。コード0のビット0が最初のコードバイトのビット0で、サンプルは昇順に続きます。63個のコードは252ビット（H）または189ビット（L/L+）を占めるため、コード領域は4ビット（H）または3ビット（L/L+）の0ビットでバイト境界までパディングされます。したがって、チャネルフラグメントは H で34バイト、L/L+ で26バイトです。

Index フィールドは ADPCM のステップインデックスで、標本値ではありません。各フラグメントの予測器（標本値）は `0` から始まり格納されないので、63個のコードがフラグメントの63個の出力標本を作ります。別の初期標本はありません。

正確なファイルサイズは `16 + f * channel_count * fragment_size` です。算術演算はオーバーフローを検査しなければなりません。

最後のフラグメントでは、最後のサンプルより後のコードスロットは0でなければなりません。バイトパディングと合わせ、フラグメント内で最後に使うコードより後のビットはすべて0です。デコーダーは宣言されたチャネルあたりのサンプル数だけを出力します。

## デコード

各チャネルフラグメントは単独で復号されます。フラグメントの最初のコードで、チャネルの状態を予測器 `0`、ステップインデックス `Index` に設定します。前のフラグメントからは何も引き継がず、ステレオの各チャネルは独立しています。

各コードについて順に、デコーダーは現在のステップ `s = STEPS[index]` からバリアントの符号付き差分 `delta` を求め、`predictor = clamp(predictor + delta, -32768, 32767)`、`index = clamp(index + adjustment, 0, 88)` の順に更新します。コードの再構成値は更新後の予測器です。出力サンプルは、再構成値にフラグメント音量を掛け、最近接丸め（同点は0から遠い方）したものです:

`output = sign(p) * ((|p| + 127) / 255)`。ここで `p = reconstructed * volume`、`/` は整数除算です。

音量 `0` は無音に復号されます。

### SQV4H

H は IMA ADPCM です。コードのビット3は符号（`1` は減算）で、ビット0–2は大きさです。89エントリーのステップテーブル `STEPS` は次のとおりです:

`[7,8,9,10,11,12,13,14,16,17,19,21,23,25,28,31,34,37,41,45,50,55,60,66,73,80,88,97,107,118,130,143,157,173,190,209,230,253,279,307,337,371,408,449,494,544,598,658,724,796,876,963,1060,1166,1282,1411,1552,1707,1878,2066,2272,2499,2749,3024,3327,3660,4026,4428,4871,5358,5894,6484,7132,7845,8630,9493,10442,11487,12635,13899,15289,16818,18500,20350,22385,24623,27086,29794,32767]`

大きさ `m = code & 7` に対し、`diff = (s >> 3) + ((m & 1) != 0 ? s >> 2 : 0) + ((m & 2) != 0 ? s >> 1 : 0) + ((m & 4) != 0 ? s : 0)` です。フルコードでインデックス化されるインデックス調整値は `[-1,-1,-1,-1,2,4,6,8,-1,-1,-1,-1,2,4,6,8]` です。

### SQV4L

L のコードは3ビットです。ビット2は符号（`1` は減算）、ビット0–1は大きさ `m` を選択します。正の差分は `(level[m]*s + 4) / 8`（整数除算）で、レベルは `[1,3,5,7]` です。`m` でインデックス化されるインデックス調整値は `[-1,2,4,6]` です。

### SQV4L+

L+ は、L と同じ符号、大きさ、予測器更新、インデックス調整を使い、レベルは `[1,2,3,14]` です。レベルは固定であり、デコーダーは実行時にレベルを最適化してはなりません。

このレベルは、等差数列を除くすべての整数タプル `(a,b,c,d)`（`1 <= a < b < c < d <= 15`）から、6つのモノラルフィクスチャを連続した予測器（フィクスチャごとにリセット、ゲイン1）でエンコード・デコードし、合計二乗誤差が最小のもの（同点は辞書順）として選びました。フィクスチャは、無音（0が1024サンプル）、インパルス（1024サンプル、サンプル0 = 32767、サンプル511 = -32768、他は0）、のこぎり波（`-32768 + (i mod 256)*256`、1024サンプル）、ランプ（`-32768 + floor(i*65535/1023)`、1024サンプル）、矩形波（`i mod 128 < 64 ? 24576 : -24576`、1024サンプル）、および `src/devices/sgu/sqv4.rs` の128サンプルのテーブル `L_PLUS_BENCH_TONE` を繰り返した8192サンプルのトーンです。勝者 `[1,2,3,14]` の13312サンプルに対する合計二乗誤差は `279448221728` です（テスト `l_plus_codebook_benchmark_is_reproducible`）。

## エンコード

エンコーダーは各チャネルフラグメントを、その入力サンプル `x[0..k)`（`1 <= k <= 63`）だけから独立に処理します。処理は決定的で、34SI22 の録音とファイルエンコーダーは同一のバイト列を出力します。

1. **Volume。** `peak = max |x[i]|`（`|-32768| = 32768`）とし、`Volume = min(255, ceil(peak * 255 / 32767))`。すべて0のフラグメントは音量 `0` で、エンコーダーはインデックス `0` とすべて0のコードを書きます。
2. **正規化。** 各サンプルをフラグメントのフルスケールへ拡大します: `n[i] = clamp(round(x[i] * 255 / Volume), -32768, 32767)`（最近接丸め、同点は0から遠い方）。これにより小さいフラグメントも大きいフラグメントと同じ相対精度で量子化され、固定ゲインでは小音量で残る量子化誤差が減ります。
3. **コード選択**（与えた初期インデックスと予測器 `0` から開始）:
   - H は、`n[i]` と予測器の差の絶対値を `s`、`s/2`、`s/4` とこの順で比較し、満たしたしきい値ごとに大きさビット2、1、0を立て、そのしきい値を残りの差から引きます。`n[i]` が予測器より小さいときに限り符号ビットを立てます。
   - L と L+ は8つのコードすべてを評価し、各差分を16ビットにクランプして予測器へ適用し、`n[i]` との絶対誤差が最小のコードを選びます。同点の場合は数値が最小のコードです。
   - 選んだコードで、次のサンプルの前にデコード規則どおり予測器とインデックスを更新します。
4. **Index。** エンコーダーは初期インデックス `0..88` のすべてについて手順3を行い、`sum((x[i] - output[i])^2)`（`output` はデコード規則で音量を適用した値）が最小のものを選びます。同点の場合は最小のインデックスです。

エンコーダーは手順1の前に入力へ線形のプリゲインを掛けてもかまいません（参照実装の `encode_interleaved` と `sqv4_convert` は `volume` を受け取り、`x * volume / 255` を0方向に切り捨てて適用します）。プリゲインはファイルに保存されません。

## 検証

デコーダーは次を拒否しなければなりません: ヘッダー不足、不正なマジック、未対応のバージョン、0–2以外のバリアント、1・2以外のチャネル数、0以外の予約バイト、レート0、正確なサイズ以外のファイル長（切り詰めや末尾の余分なバイト）、88を超えるインデックスバイト、フラグメント内で最後に使うコードより後の0以外のビット。

ファイル全体がそろう前にフラグメントを消費するストリーミングデコーダー（34SI22）は先読み検証ができません。その場合も正しいデータに対しては上記のデコードを行わなければならず、88を超えるインデックスバイトは88として扱います。

## ハードウェア再生コンテナー

S3W2 SQV4 波形（SGU v3）は、PCM RAM 内に完全に配置されたバージョン3ファイルを使用します。開始レジスターは16バイトのヘッダーを指し、終了レジスターはファイル全体を含む排他的バイトアドレスです。モノラルファイルのみを受け付けます。PCM サンプルレートレジスターが再生タイミングを制御し、ファイルのサンプルレートはメタデータのみです。ループアドレスが0または開始アドレスと等しい場合は最初のフラグメントから再開します。それ以外のループアドレスはヘッダーの後にあるチャネルフラグメントの先頭バイト（音量）を指さなければならず、再生はそのフラグメントだけを復号して再開します。不正なファイル（上記の検証に失敗するもの）、SGU の世代と合わないバージョン、モノラル以外のデータ、RAM 範囲外、または無効なループ境界がある場合、チャネルは範囲外を読み取らずに非アクティブになり、無音を出力します。

## ImHex pattern

`tools/imhex/sqv4.hexpat` はバージョン1–3のヘッダーとバリアントごとのチャネルフラグメントを表示します。パックされた ADPCM コードバイトは raw 表示で、コードのデコードは行いません。

## 付録 A: バージョン1と2

バージョン1・2のヘッダーは上記と同じです（バージョンバイトは `1` または `2`）。チャネルフラグメントは64サンプルで、音量バイト1つと、上記と同じ方法でパックされた64個のコード（H は32バイト、L/L+ は24バイト）から成ります。インデックスバイトはなく、満杯のフラグメント内にパディングはありません。各チャネルの予測器とインデックスはファイル開始時に一度だけ `0` に初期化され、全フラグメントにわたって引き継がれるため、フラグメントを単独で復号することはできません。出力は `reconstructed * volume / 255` を0方向に切り捨てた値で、エンコーダーは音量引数をそのまま全フラグメントに書いていました（正規化なし）。H と L の規則は上記と同じで、L+ のレベルはバージョン1が `[10,11,12,14]`、バージョン2が `[1,2,3,14]` です。最後のフラグメントの未使用コードスロットは0です。バージョン1・2のループアドレスはフラグメントの音量バイトを指し、ファイル先頭から復号して到達します。
