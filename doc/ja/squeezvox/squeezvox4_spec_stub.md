# SqueezVOX 4 (SQV4) バージョン1および2仕様

この文書は、SQV4H、SQV4L、SQV4L+ の規範的なバージョン1およびバージョン2のワイヤ形式と予測器規則を定義します。バージョン2は、復元レベルの変更がデコードされる PCM を変えるためバージョン管理される L+ コードブックを除き、バージョン1のデコードを維持します。新しいエンコーダーはバージョン2を書き込まなければなりません。デコーダーはバージョン1および2をサポートしなければなりません。特に明記しない限り、複数バイト整数は符号なしリトルエンディアンです。PCM 入出力は符号付き16ビットリトルエンディアンのインターリーブサンプルです。デコーダーは不正または非正規のファイル長を拒否しなければなりません。エンコーダーはここで定義する形式を厳密に出力しなければなりません。

## ファイル形式

固定ヘッダーは16バイトです:

| オフセット | サイズ | 意味 |
| --- | ---: | --- |
| 0 | 4 | ASCII `SQV4` |
| 4 | 1 | バージョン: `1` または `2`; エンコーダーは `2` を書き込まなければならない |
| 5 | 1 | バリアント: `0` = H, `1` = L, `2` = L+ |
| 6 | 1 | チャネル数: `1` モノラルまたは `2` ステレオ |
| 7 | 1 | 予約済み、0でなければならない |
| 8 | 4 | サンプルレート (Hz)、0以外でなければならない |
| 12 | 4 | チャネルあたりのサンプル数 |

空ストリームのサンプル数は0で、ヘッダーのみで構成されます。宣言されたサンプルレートはメタデータであり、デコード時にリサンプリングは行いません。

ペイロードは時間順のフラグメントで構成されます。各フラグメントでは、チャネルは昇順に並びます。各チャネルフラグメントは、符号なし音量バイト1つと、その後に続く64個のパック済みコードで構成されます。H は4ビットコード（ペイロード32バイト）を使用します。L および L+ は3ビットコード（ペイロード24バイト）を使用します。コードは最下位ビット優先でパックされます。コードのビット0がストリームの最初のビットであり、サンプルはサンプルインデックス昇順でパックされます。最終フラグメントの未使用コードスロットは0でなければなりません。デコーダーは宣言されたチャネルあたりのサンプル数だけを出力し、パディングスロットは出力に含めません。

各フラグメントの音量は `[0,255]` の線形ゲインです。デコードでは、符号付き整数除算を0方向への丸めで適用します: `output = reconstructed_predictor * volume / 255`。エンコーダーの `volume` 引数は各チャネルフラグメントに変更せず書き込まれます。

チャネルあたり n サンプルの場合、チャネルあたりのフラグメント数は `f = ceil(n/64)` であり、`n=0` の場合を含みます。正確なファイルサイズは `16 + f * channel_count * (1 + payload_bytes_per_fragment)` です。ペイロードサイズは H で32、L/L+ で24です。算術演算はオーバーフローを検査しなければなりません。デコーダーは、ヘッダー不足、不正なマジック/バージョン/バリアント/チャネル数/予約バイト、レート0、ペイロードの切り詰め、または末尾に余分なバイトがある場合を拒否しなければなりません。

各チャネルは独立した予測器とステップインデックスを持ち、ファイル開始時に一度だけ予測器 `0`、インデックス `0` で初期化され、その後の全フラグメントにわたって保持されます。フラグメントには予測器状態が含まれません。任意のフレーム位置へのシークは保証されません。ステレオのチャネル状態は独立しています。

## 共通 ADPCM 状態

コードの符号付き差分 `delta` を決定した後、`predictor = clamp(predictor + delta, -32768, 32767)` を更新し、次に `index = clamp(index + adjustment, 0, 88)` を更新します。コードの再構成サンプルは更新後の予測器です。エンコーダーのコード選択では、このクランプ後の再構成サンプルを評価します。初期状態とすべての状態遷移は、エンコードとデコードに同じように適用されます。

### SQV4H

H は IMA ADPCM です。コードのビット3は符号（`1` は減算）で、ビット0–2は大きさです。89エントリーのステップテーブルは次のとおりです:

`[7,8,9,10,11,12,13,14,16,17,19,21,23,25,28,31,34,37,41,45,50,55,60,66,73,80,88,97,107,118,130,143,157,173,190,209,230,253,279,307,337,371,408,449,494,544,598,658,724,796,876,963,1060,1166,1282,1411,1552,1707,1878,2066,2272,2499,2749,3024,3327,3660,4026,4428,4871,5358,5894,6484,7132,7845,8630,9493,10442,11487,12635,13899,15289,16818,18500,20350,22385,24623,27086,29794,32767]`

大きさ `m = code & 7`、現在のステップ `s` に対し、`diff = (s >> 3) + ((m & 1) != 0 ? s >> 2 : 0) + ((m & 2) != 0 ? s >> 1 : 0) + ((m & 4) != 0 ? s : 0)` です。フルコードでインデックス化されるインデックス調整値は `[-1,-1,-1,-1,2,4,6,8,-1,-1,-1,-1,2,4,6,8]` です。

H エンコーダーは、入力と予測器の差の絶対値を `s`、`s/2`、`s/4` とこの順で比較します。各しきい値を満たす場合、それぞれ大きさビット2、1、0を設定し、そのしきい値を残りの差から差し引きます。入力が現在の予測器より小さい場合に限り、符号ビットを設定します。

### SQV4L

L は3ビットコードを使用します。ビット2は符号（`1` は減算）で、ビット0–1は大きさを選択します。`[0,3]` の大きさ `m` に対する正の再構成レベルは `[(1*s+4)/8, (3*s+4)/8, (5*s+4)/8, (7*s+4)/8]` で、整数除算を使用します。符号はこのレベルを反転します。大きさに対するインデックス調整値は `[-1,2,4,6]` です。

### SQV4L+

L+ は、L と同じ3ビットの符号、大きさ、予測器更新、インデックス調整を使用します。正の差分は `(level*s+4)/8` です。コードのビット2は差分を反転します。

バージョン1はコードブック `[10,11,12,14]` を使用します。バージョン2はコードブック `[1,2,3,14]` を使用します。デコーダーはファイルのバージョンに応じてコードブックを選択しなければなりません。エンコーダーはバージョン2のコードブックを使用して、バージョン `2` を書き込まなければなりません。これにより、既存のバージョン1 L+ ファイルの再生を維持しながら、バージョン2の音質を改善します。

両コードブックは、等差数列を除外したすべての整数タプル `(a,b,c,d)`（`1 <= a < b < c < d <= 15`）から選択されます。各タプルについて、各フィクスチャで予測器/インデックスをリセットし、音量255で各フィクスチャを順にエンコードしてからデコードします。合計二乗誤差を最小化するタプルを選び、同点の場合は辞書順とします。

バージョン1のベンチマークでは、1024サンプルのモノラルフィクスチャ5つを使用します: 無音（すべてゼロ）、インパルス（サンプル0 = 32767、サンプル511 = -32768、その他はすべてゼロ）、のこぎり波（`-32768 + (i mod 256)*256`）、ランプ（`-32768 + floor(i*65535/1023)`）、矩形波（`i mod 128 < 64 ? 24576 : -24576`）。選択されるのは `[10,11,12,14]` であり、5120サンプルに対する合計二乗誤差は `252189726976` です。

バージョン2のベンチマークでは、上記5つのフィクスチャに加えて、この128サンプルの符号付き PCM テーブルを64回繰り返して作る8192サンプルのトーンフィクスチャを使用します:

`[0,8926,15150,17259,15693,12291,9111,7209,6123,4321,355,-5996,-13304,-19056,-20923,-17999,-11314,-3305,3432,7423,8889,9316,10311,12445,14782,15391,12542,5883,-3121,-11761,-17368,-18600,-16000,-11529,-7368,-4690,-3121,-1188,2542,8320,14782,19516,20311,16387,8889,352,-6568,-10376,-11314,-10928,-10923,-11985,-13304,-13067,-9645,-2750,6123,14280,19111,19362,15693,10188,5150,1855,0,-1855,-5150,-10188,-15693,-19362,-19111,-14280,-6123,2750,9645,13067,13304,11985,10923,10928,11314,10376,6568,-352,-8889,-16387,-20311,-19516,-14782,-8320,-2542,1188,3121,4690,7368,11529,16000,18600,17368,11761,3121,-5883,-12542,-15391,-14782,-12445,-10311,-9316,-8889,-7423,-3432,3305,11314,17999,20923,19056,13304,5996,-355,-4321,-6123,-7209,-9111,-12291,-15693,-17259,-15150,-8926]`

バージョン2の勝者は `[1,2,3,14]` であり、13312サンプルに対する合計二乗誤差は `279448221728` です。コードブックレベルはエンコード中およびデコード中に固定のままでなければなりません。デコーダーは実行時にレベルを最適化してはなりません。

## エンコーダーの選択

L および L+ では、各入力サンプルについて、エンコーダーは符号の両方を含む、すべての有効な大きさを評価します。候補差分を現在の予測器に適用し、16ビット範囲にクランプした後、入力サンプルとの絶対誤差を最小にするコードを選択します。同点の場合は数値が最小のコードを選択します。コードを出力し、次のサンプルを処理する前に通常の状態規則で予測器とインデックスを更新します。H は上記のしきい値量子化器を使用します。エンコーダーは最終フラグメントのパディングに0コードを書き込みますが、存在しないサンプルについて予測器/インデックスを進めません。

## ハードウェア再生コンテナー

S3W2 SQV4 波形は、PCM RAM 内に完全に配置されたファイルを使用します。開始レジスターは16バイトのファイルヘッダーを指し、終了レジスターはファイル全体を含む排他的バイトアドレスです。このハードウェア再生経路はモノラルファイルのみを受け付けます。PCM サンプルレートレジスターは引き続き再生タイミングを制御し、ファイルのサンプルレートはメタデータのみです。ループアドレスが0または開始アドレスと等しい場合は、ファイルヘッダーから再開します。それ以外のループアドレスは、ヘッダーの後にあるチャネルフラグメント（音量バイト）の先頭バイトを指さなければならず、独立したシーク状態として解釈してはなりません。ループ時は、選択したフラグメントまで初期予測器/インデックス状態から再構成します。不正なヘッダー、モノラル以外のデータ、RAM 範囲外、不完全なファイル、または無効なループ境界がある場合、チャネルは範囲外を読み取らずに非アクティブになり、無音を出力します。

## ImHex pattern

`tools/imhex/sqv4.hexpat` は v1/v2 header と variant ごとの channel fragment を
表示します。パックされた ADPCM code byte は raw 表示で、code のデコードは行いません。
