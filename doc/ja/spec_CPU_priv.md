# SRC32 拡張P（大文字）— 特権レベルとシステムコール

Revision 1.0 (2026-10-21)。状態: 全CPU方式で実装済み
（`src/cpu_privilege.rs`、`src/cpu.rs`、`src/cpu_pipeline.rs`）。

拡張Pは拡張Iに依存します。大文字と小文字は区別されます。小文字の`p`
（パイプライン処理、[[doc/ja/spec_CPU_p|拡張p仕様]]）は別の拡張です。

設計方針は **わかりやすさ優先** です。モードは2つ、トラップの入口規則は1つ、
復帰規則は1つ、新しい命令は3つです。

## 1. 概要

| 項目 | 値 |
|---|---|
| モード | スーパーバイザー（S）とユーザー（U）。リセットはSで始まる。 |
| CPUID | `CPU_FEATURES` bit 8（`EXT_P = 0x100`）。scalar／cached／JITは`0x13F`、pipelineは`0x1BF`。 |
| 新しい命令 | `SYSCALL imm16`（`0x23`）、`MFSR rd, sr`（`0x24`）、`MTSR sr, rs`（`0x25`） |
| 特権命令 | `HALT`、`IRET`、`MFSR`、`MTSR` |
| バンクレジスター | `R28`（SP）、`R29`（FP）、`R30`（GP）はSとUで別々 |
| ユーザーのメモリー | 既定は拒否。Sが設定する8個の領域でR/W/Xを許可。CPU予約領域にはUから一切アクセスできない。 |
| 例外 | 不正命令、バスエラー、SYSCALL、特権命令、保護違反 |

Sから出ないプログラムは、§11の変更点を除き従来どおりに動きます。

## 2. モード

- **S（スーパーバイザー）**: すべての命令とアドレスを使えます。リセット、IRQ受付、
  すべての例外でSに入ります。
- **U（ユーザー）**: `HALT`、`IRET`、`MFSR`、`MTSR`は特権命令例外になります。
  命令フェッチ、ロード、ストアはすべて保護領域（§7）で検査します。

モードが変わるのはトラップ（U→S）と`IRET`（保存したモードに戻る）だけです。
ユーザープログラムを始めるには、Sが`EPC`と`STATUS.PU`を設定して`IRET`を実行します（§10.1）。

### 2.1 起動方針

- リセットは常にSで始まります。既存プログラム、raw `.bin`、保護なしの`.wax`は従来どおりに動きます。
- ユーザーモードは実行ファイルごとのオプトインです。`PROTECTED`フラグ付きの`.wax`
  （[[doc/ja/spec_WAX|WAX仕様]]）がスタックとblockごとのR/W/X権限を宣言します。
- そのimageのS→U受け渡しはBIOSのWAX loaderが行います。ホストの直接ロードはUに入らず、
  保護付きimageを拒否します。

## 3. 命令

3命令ともNormal modeの即値形式`[op:6][rd:5][rs1:5][imm16:16]`です。
Short modeの形式はありません。Short modeのルーチンからは先に`S.RET`で抜けます。

### 3.1 `SYSCALL imm16` — opcode `0x23`

- `imm16[7:0]`: システムコール番号、`0..255`。
- `imm16[15:8]`: コンテキストbyte。OS用に予約します。不要なら0にします。CPUはコピーするだけです。
- `rd`と`rs1`は無視します。0にしてください。
- SでもUでも使えます。レジスターは変えません。
- 動作: `CAUSE = 0x8003_0000 | imm16`、`EPC = 次の命令のアドレス`、ベクターワード`0xFFFF000C`でトラップします。

アセンブラー: `SYSCALL n`（n = 0..255）または`SYSCALL n, ctx`（ctx = 0..255）。

### 3.2 `MFSR rd, sr` — opcode `0x24`（Sのみ）

`rd ← SR[imm16]`。`rs1`は無視します。未知の`sr`番号は不正命令です。

### 3.3 `MTSR sr, rs` — opcode `0x25`（Sのみ）

`SR[imm16] ← rs`。ソースレジスターは`rs1`フィールドで、`rd`は無視します。
未知の`sr`番号は不正命令です。読み取り専用bitは値を保ちます。`MTSR`は次の命令より前に効きます。

アセンブラー: `MFSR R1, STATUS`、`MTSR EPC, R2`。SRオペランドには§4の名前か番号を書けます。

## 4. システムレジスター（SR）

| SR | 名前 | アクセス | 意味 |
|---:|---|---|---|
| `0x00` | `STATUS` | R/W | モードと割り込みの状態（§4.1） |
| `0x01` | `EPC` | R/W | `IRET`の戻り先 |
| `0x02` | `CAUSE` | R/W | 直前のトラップの理由（§5） |
| `0x08` | `USP` | R/W | ユーザー側の`R28` |
| `0x09` | `UFP` | R/W | ユーザー側の`R29` |
| `0x0A` | `UGP` | R/W | ユーザー側の`R30` |
| `0x10 + 4n` | `RGNn_START` | R/W | 領域`n`の開始アドレス（含む）、`n = 0..7` |
| `0x11 + 4n` | `RGNn_END` | R/W | 領域`n`の終了アドレス（含まない） |
| `0x12 + 4n` | `RGNn_FLAGS` | R/W | 領域`n`の権限bit（§7） |

これ以外の番号（`0x13 + 4n`を含む）は未知です。

`USP`／`UFP`／`UGP`は常に **ユーザー側** のコピーを指します。Sのコードはこれでユーザー
コンテキストを準備・保存します。Uモードでは`R28`〜`R30`そのものがユーザー側です。

### 4.1 STATUS

| Bit | 名前 | 意味 |
|---:|---|---|
| 0 | `IE` | 割り込み許可 |
| 1 | `PIE` | 直前のトラップ前の`IE` |
| 2 | `U` | 現在のモード。0 = S、1 = U。**読み取り専用。** |
| 3 | `PU` | 直前のトラップ前のモード |
| 4 | `PSM` | 直前のトラップ前の命令モード。0 = Normal、1 = Short |
| 31..5 | — | 0を読み出し、書き込みは無視 |

リセット値: `IE=1, PIE=1, U=0, PU=0, PSM=0`（`0x03`）。

`MTSR STATUS`で`IE=1`にすると割り込みが有効になります。Sのコードは`EPC`、`CAUSE`、
`STATUS`を保存した後にこれで多重割り込みを許可できます。

CPU状態MMIOワード`0xFFFF028C`は同じSTATUS値を表示します。従来どおり、CPU状態MMIOへの
ゲストのstoreはcommit時に上書きされます。`MTSR`を使ってください。ホストのデバッガーが
このワードへ書くと`IE`、`PIE`、`PU`、`PSM`を変えられます。`U`はここでも読み取り専用です。

## 5. CAUSE

| CAUSE | トラップ | `EPC` | ベクター |
|---|---|---|---|
| `0x0000_000n` | IRQ `n`（0..15） | 次の命令 | IRQスロット`0xFFFF0100 + 4n`（命令） |
| `0x8001_0000` | 不正命令 | 例外を起こした命令 | `0xFFFF0004` |
| `0x8002_0000` | バスエラー | 例外を起こした命令 | `0xFFFF0008` |
| `0x8003_xxxx` | `SYSCALL`（`xxxx` = imm16） | 次の命令 | `0xFFFF000C` |
| `0x8004_0000` | Uでの特権命令 | 例外を起こした命令 | `0xFFFF0004` |
| `0x8005_000k` | Uでの保護違反 | 例外を起こした命令 | `0xFFFF0008` |

構成:

- bit 31: 0 = IRQ、1 = 例外。
- bit 23..16: 例外コード（1..5）。
- bit 15..0: 詳細。SYSCALLは`imm16`（bit 7..0 = 番号、15..8 = コンテキスト）。
  保護違反は`k` = 1 読み出し、2 書き込み、4 命令フェッチ。

IRQの値は変わらないので、CAUSEを0..15と比べる既存のディスパッチャーはそのまま動きます。

命令の問題は不正命令ベクター、アクセスの問題はバスエラーベクターを共有します。区別はCAUSEで行います。

## 6. トラップの入口とIRET

すべてのトラップ（IRQと例外）は次のとおりに動きます。

```
EPC        = §5を参照
CAUSE      = §5を参照
STATUS.PIE = STATUS.IE
STATUS.IE  = 0
STATUS.PU  = STATUS.U
STATUS.PSM = (INSTR_MODE == Short)
if STATUS.U == 1: R28..R30をSのバンクに切り替え
STATUS.U   = 0
INSTR_MODE = Normal
PC         = IRQスロットのアドレス、または例外ベクターに格納されたワード
```

例外ベクターワードが自分自身のアドレス（リセット時の既定値）のままなら、CPUはループせず
そのベクターで停止します。既定のベクターワードは`0xFFFF0004`、`0xFFFF0008`、`0xFFFF000C`です。

保留中のIRQラッチは例外をまたいで保持します。`IE`が1に戻ると受け付けます。

`IRET`（Sのみ）:

```
PC         = EPC
STATUS.IE  = STATUS.PIE
INSTR_MODE = STATUS.PSM ? Short : Normal
if STATUS.PU == 1: R28..R30をUのバンクに切り替え
STATUS.U   = STATUS.PU
```

`IRET`の後も`PIE`、`PU`、`PSM`は値を保ちます。

### 6.1 精密性

例外は精密です。例外を起こした命令は何もしません。拒否されたstoreは書き込まず、
拒否されたloadはバスを読みません。`SYSCALL`はトラップ状態以外を変えません。
古い命令は完了済みで、新しい命令は始まっていません。

## 7. ユーザーモードのメモリー保護

検査はUモードだけです。Sモードは検査しません。

1. アクセスのbyteが`0xFFFF0000..0xFFFFFFFF`（CPUベクター、IRQC、CPU状態）に1つでもかかれば拒否します。
2. それ以外は、アクセスの **すべてのbyte** が、必要な権限を許可する *有効な* 領域の少なくとも1つに入っている必要があります。

| アクセス | 権限 |
|---|---|
| ロード（`LD`、`LDH`、`LDB`、`S.LD`） | R（`FLAGS` bit 0） |
| ストア（`ST`、`STH`、`STB`、`S.ST`） | W（`FLAGS` bit 1） |
| 命令フェッチ（Normalは4 byte、Shortは2 byte） | X（`FLAGS` bit 2） |

領域は`FLAGS & 7 != 0`かつ`START < END`のとき有効で、`START <= addr < END`を覆います。
領域は重なってもよく、権限は合算します（どれか1つがbitを許可すればそのbyteは許可）。
`FLAGS`のbit 31..3は0を読み出します。

リセット時はすべての領域が0なので、Sが許可するまでUからは何もアクセスできません。

拒否されたアクセスは、バスに触れる前に保護違反（§5）になります。

デバイスの窓（例: VDP `0x80000000..0x80010000`）を許可すると、ゲームがそのデバイスを
直接操作できます。DMAC、BMC、IDC、拡張カードは、ユーザーコードを信頼できない限り許可しないでください。
DMAはバスマスターで、検査されません。

## 8. バンクレジスター

`R28`、`R29`、`R30`は2組あります。SモードではSのコピー、UモードではUのコピーを使います。
`R31`（LR）を含む他のレジスターは共有です。

これにより、既存のIRQベクターの書き方（スロット内の`JR R30`）とsolのディスパッチャーが安全に
なります。Uからのトラップでは`R30`と`R28`がカーネルの値なので、ユーザーコードはハンドラーや
そのスタックを乗っ取れません。

CPU状態MMIOビュー`0xFFFF0200..`とデバッガーは、現在のモードのバンクを表示します。

## 9. 実装メモ（エミュレーター）

- 全CPU方式が`src/cpu_privilege.rs`を共有します。SR番号、CAUSE値、STATUS bit、領域検査、バンク切り替えです。
- Pipeline: `SYSCALL`、`MTSR`、`IRET`とすべての例外はcommit時に処理してパイプラインをflushし、
  新しいPCからフェッチをやり直します。そのため、実行中の命令の下でモード、バンク、領域が変わることはありません。
- JIT: native blockはSモードでだけ動きます。UモードはCached interpreterを使います。
  `SYSCALL`、`MFSR`、`MTSR`は常にblockを終わらせます。
- spin-loop fast-forwardは特権状態も比較します。

## 10. 例

### 10.1 ユーザープログラムの開始

```
    ; 領域0: ユーザーのコードとデータ 0x00100000..0x00200000、R/W/X
    LDIH R1, 0x0010
    LDIL R1, 0x0000
    MTSR RGN0_START, R1
    LDIH R1, 0x0020
    LDIL R1, 0x0000
    MTSR RGN0_END, R1
    ADDI R1, R0, 7
    MTSR RGN0_FLAGS, R1
    ; ユーザースタックの先頭
    LDIH R1, 0x0020
    LDIL R1, 0x0000
    MTSR USP, R1
    ; 割り込み許可つきでuser_mainからUに入る
    LDIH R1, user_main
    LDIL R1, user_main
    MTSR EPC, R1
    ADDI R1, R0, 0x0B      ; PU=1, PIE=1, IE=1
    MTSR STATUS, R1
    IRET
```

### 10.2 SYSCALLハンドラーの骨組み

```
    ; 0xFFFF000C には syscall_entry を格納しておく
syscall_entry:
    ; Uから呼ばれても、ここでのR28はSのスタック
    ADDI R28, R28, -8
    ST [R28 + 0], R13
    ST [R28 + 4], R14
    MFSR R13, CAUSE
    ADDI R14, R0, 0xFF
    AND R13, R13, R14      ; R13 = 番号（CAUSE bit 7..0）
    ...                    ; R13で分岐
    LD R14, [R28 + 4]
    LD R13, [R28 + 0]
    ADDI R28, R28, 8
    IRET                   ; SYSCALLの次に戻る
```

## 11. 以前のリビジョンとの互換性

- バスエラーの`CAUSE`は`2`から`0x8002_0000`に変わります。IRQ2は`CAUSE = 2`のままなので、両者は衝突しなくなります。
- 不正命令は、ホストpanicでエミュレーターを止めずに例外になります。
- `IRET`は`IE`を常に1にせず、`PIE`から戻します。IRQは`IE = 1`のときしか受け付けないので、IRQハンドラーでは同じ結果です。
- 例外は保留中のIRQラッチを保持します（以前はバスエラーの入口で消していました）。
- Pipeline: `IRET`はEXではなくcommitで分岐するので、数サイクル多くかかります。
- `0xFFFF0104`はIRQ1のスロットです。以前の草案ではSYSCALLをそこに置いていましたが、SYSCALLのベクターは`0xFFFF000C`です。
