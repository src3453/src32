# COW v1 サイドカーフォーマット

COW v1 は不変のベースイメージに対する書き込み可能なオーバーレイを保存します。ベースは変更されません。通常動作中、サイドカーは追記専用であり、変更された各論理ブロックについて最新の全ブロック置換データを格納します。整数はリトルエンディアンです。圧縮およびディスク上のインデックスはありません。

## ヘッダー

ヘッダーは正確に 64 バイトです:

| オフセット | サイズ | フィールド |
|---|---:|---|
| `0x00` | 8 | マジック `CPTCOW1\0` |
| `0x08` | 2 | バージョン `1` |
| `0x0A` | 2 | ヘッダーサイズ `64` |
| `0x0C` | 2 | デバイス種別: `0` 汎用、`1` ディスク、`2` EEPROM、`3` SRAM |
| `0x0E` | 2 | フラグ。現在は `0` |
| `0x10` | 4 | ブロックサイズ、1～4096 バイト |
| `0x14` | 8 | 論理イメージサイズ、0 以外 |
| `0x1C` | 32 | 論理ベース全体の SHA-256 |
| `0x3C` | 4 | `0x00..0x3B` の CRC32C |

ベースはヘッダーの論理サイズと正確に一致しなければなりません。オープン時にその SHA-256、device type、block size、version、header size、flags、header CRC を検証します。不一致はエラーであり、既存のサイドカーを変更しません。CRC32C は Castagnoli CRC です。

## レコード

各レコードは 32 バイトのヘッダーに続いて、全ブロック分のデータを正確に 1 つ持ちます:

| オフセット | サイズ | フィールド |
|---|---:|---|
| `0x00` | 4 | マジック `BLK1` |
| `0x04` | 8 | ブロックインデックス |
| `0x0C` | 8 | シーケンス番号。1 から始まり、正確に 1 ずつ増加 |
| `0x14` | 4 | 後続するブロック全体の CRC32C |
| `0x18` | 4 | このフィールドを 0 にしたレコードヘッダーの CRC32C |
| `0x1C` | 4 | 予約済み。0 でなければならない |

ブロックインデックスは `ceil(logical_size / block_size)` 未満でなければなりません。最後の論理ブロックはベースイメージの範囲を越えてもよく、全ブロックとして保存されます。論理サイズを越えるバイトは無視されます。同じインデックスへの書き込みはレコードを追記し、最後の完全なレコードが有効になります。不正なシーケンス、範囲、予約フィールド、CRC を含む完全な不正レコードは、サイドカーを無効にします。最後のレコードが部分的な場合は回復可能な末尾です。検証ではその存在を報告し、baking では無視し、実行時には次の追記前に最後の完全なレコード境界まで切り詰めます。

writer は完全な 32 バイトのレコードヘッダーと全ブロック分のデータを追記して `sync_data` を呼び出します。メモリ内の最新ブロックインデックス／シーケンスは sync 成功後にのみ更新します。追記に失敗した場合、直前のコミット済み境界までロールバックします。ロールバックにも失敗した場合、そのオーバーレイへの以後の書き込みは失敗します。新規サイドカーでは、レコードを追記する前に完全な 64 バイトのヘッダーを sync します。

パッケージまたは実行時ディスクを開くとき、存在しないサイドカーは作成しません。最初のコミット済み書き込みまでは空のオーバーレイです。その時点で必要に応じて親ディレクトリとサイドカーを作成し、最初のレコードの前に完全な 64 バイトのヘッダーを書き込んで sync します。読み取り専用の検証と baking では、存在しないサイドカーをエラー入力として扱います。

## Rust API

`cpt32::cow::BaseImage` は、不変の `File(File)` または `Bytes(Arc<[u8]>)` バッキングイメージです。`CowOverlay::open(base, path, device_type, block_size)` はオーバーレイを開くか作成します。サイドカーが存在しない場合、空のオーバーレイとして開始します。`read_at(&mut self, offset, output)` はオーバーレイとベースを通して読み込み、論理イメージの範囲を越える範囲を拒否します。`write_block(&mut self, block_index, data)` は完全なブロックをちょうど 1 つ受け取ります。

`scan_cow(base, path, device_type, block_size)` は読み取り専用で `CowScan` を返します。存在しないサイドカーを拒否し、完全なレコードをすべて検証します。`CowScan.records` は完全なレコード数、`recoverable_tail` は最後に不完全なレコードがあることを示し、`valid_end` は最後のコミット済みバイトオフセット、`latest_blocks` は変更された各ブロックインデックスを COW ファイル内のデータバイトオフセットに対応付けます。このインデックスを使うと、後続の baker はレコードを再走査せずに最新ブロックを読み込んで適用できます。`logical_size`、`block_size`、`device_type` は検証済みストアを記述します。scanner は COW ファイルを変更しません。

## ツールの使用

オフラインユーティリティが受け付けるコマンドは次のものだけです:

```text
cpt32-tool cow verify BASE COW
cpt32-tool cow bake BASE COW -o OUTPUT
```

`verify` は完全なレコード数、一意な変更済みブロック数、および回復可能な末尾の有無を報告します。完全なレコードがすべて有効なら、その末尾があっても成功します。`bake` はブロックごとに最新の完全なレコードだけを raw base のコピーへ適用し、どちらの入力も変更しません。既存の出力、または入力のいずれかと別名になる出力は拒否します。成功した出力は sync され、サイズが検査されます。COW ファイルが存在しない場合、どちらのコマンドもエラーになります。Compaction はこのフォーマット／ツールのバージョンには含まれません。
